Bolt はすべての AI ペルソナを **エージェント** という名前付きの単位で扱います。エージェントとは、システムプロンプトと精密にスコープされたツール権限のセットの組み合わせです。あらゆるタスクに対して 1 つの汎用モデルを実行する代わりに、必要な内容 — セキュリティ監査、ドキュメント作成、フレームワーク移行の全体配線など — にアクセスとフォーカスが合致したエージェントを選択します。

## アクセスレベル

すべての組み込みエージェントには、呼び出せるツールを決定する 3 つのアクセス層のいずれかが割り当てられます。

| レベル | 付与される権限 | 一般的な用途 |
|-------|---------------------|-------------|
| **Full** | ファイルの読み込み、書き込み/編集、シェルコマンドの実行 | アクティブなコーディング、デバッグ、リファクタリング、移行 |
| **Edit** | ファイルの読み込み、書き込み/編集 — シェルなし | ドキュメント、コメントの更新、安全な文章編集 |
| **Read** | ファイルの読み込みのみ — 書き込み、シェルなし | 計画、リサーチ、コードレビュー、監査 |

## 組み込みエージェント

Bolt は 10 種類の専門エージェントを標準で提供します。TUI では <kbd>Tab</kbd> を押して切り替えます。

| エージェント | アクセス | 説明 |
|-------|--------|-------------|
| `code` | Full | デフォルト: コードの読み込み、書き込み、実行 |
| `plan` | Read | コードを変更せずにコードベースを探索して計画を作成 |
| `ask` | Read | 質問とリサーチ — ファイル編集なし |
| `code-review` | Read | 正確性、スタイル、セキュリティの観点で変更をレビュー |
| `debug` | Full | 失敗したテスト、クラッシュ、ロジックエラーをデバッグ |
| `refactor` | Full | 各ステップでテスト検証を伴う安全なリファクタリング |
| `docs` | Edit | ドキュメントとコメントの記述と更新 |
| `security` | Read | セキュリティ監査: 脆弱性、シークレット、危険なパターン |
| `migrate` | Full | フレームワークのアップグレードと依存関係の移行 |
| `perf` | Full | パフォーマンス分析と最適化 |

## サブエージェント

10 の主要エージェントに加え、Bolt はセッション中にプライマリエージェントが作業を委譲できる 2 つの組み込み **サブエージェント** を公開しています。サブエージェントを手動で選択することはありません — プライマリエージェントがサブエージェントを生成すると判断したときに自動的にディスパッチされます。

| サブエージェント | 役割 |
|----------|------|
| `@general` | 幅広い機能を必要とする複雑な複数ステップのタスク委譲 |
| `@explore` | 高速で読み取り専用のコードベース調査 — 副作用なくファイルを走査 |

<Tip>
  不慣れなコードベースを素早く理解する必要がある場合は、`ask` または `plan` エージェントから始めてください。裏側では、`@explore` サブエージェントをディスパッチしてプロジェクトを高速にインデックス化してから回答を生成できます — 1 つのファイルにも触れることなく。
</Tip>

## エージェントの切り替え

**TUI 内** — セッション中いつでも <kbd>Tab</kbd> を押して利用可能なエージェントのリストを循環できます。アクティブなエージェントはセッションフッターに表示されます。

**非対話的** — `bolt run` に `--agent <name>` を渡すと、その実行の間、特定のエージェントを固定できます。

```bash
bolt run --agent ask "what does the authentication flow do?"
bolt run --agent security "audit the API layer for injection vulnerabilities"
bolt run --agent docs "add JSDoc comments to every exported function in src/utils"
```

## エージェントの一覧表示

組み込みおよびカスタムのすべての利用可能なエージェントを、モードと権限構成と共に確認するには次のようにします。

```bash
bolt agent list
```

## カスタムエージェント

独自のエージェントは 2 通りの方法で作成できます。

### `bolt agent create` で生成する

対話型ウィザードは LLM を使ってエージェントファイルを生成し、ディスクに書き込みます。

```bash
bolt agent create
```

すべてのフラグはオプションです。非対話的に実行するには次のように指定します。

```bash
bolt agent create \
  --description "Audit GraphQL resolvers for N+1 problems and suggest DataLoader fixes" \
  --path .bolt/agents \
  --mode primary \
  --permissions read,grep,glob \
  --model anthropic/claude-opus-4-5
```

| フラグ | 説明 |
|------|-------------|
| `--description` | エージェントの目的 (生成時の LLM プロンプトとして使用) |
| `--path` | 生成されたエージェントファイルを書き込むディレクトリ |
| `--mode` | `all` (デフォルト)、`primary`、または `subagent` |
| `--permissions` | 許可する権限のカンマ区切りリスト。省略するとすべて許可。 |
| `--model` / `-m` | `provider/model` 形式で使用するモデル |

### Markdown ファイルを手動で書く

エージェントは YAML フロントマターを持つ Markdown ファイルにすぎません。プロジェクト内の `.bolt/agents/` またはグローバルエージェントディレクトリに配置します。

```markdown
---
description: "Audit GraphQL resolvers for N+1 problems"
mode: primary
permission:
  bash: deny
  edit: deny
---

You are a GraphQL performance specialist. Your job is to identify N+1 query
patterns in resolver code and recommend DataLoader-based solutions...
```

ファイル名 (`.md` を除いたもの) がエージェントの識別子になります。

### 利用可能な権限

権限は、カスタムエージェントを作成する際に制御できる粒度の細かいツールゲートです。

| 権限 | 制御対象 |
|------------|----------|
| `bash` | シェルコマンドの実行 |
| `read` | ファイルの読み込み |
| `edit` | ファイルの書き込みと編集 (`write` と `apply_patch` もゲート) |
| `glob` | ファイル glob/ディレクトリのリスト |
| `grep` | ripgrep によるファイル検索 |
| `webfetch` | Web からの HTTP フェッチ |
| `task` | サブエージェントタスクの生成 |
| `todowrite` | Todo 項目の作成と更新 |
| `websearch` | Web 検索クエリ |
| `lsp` | 言語サーバプロトコル操作 |
| `skill` | プロジェクトスキルへのアクセス |
