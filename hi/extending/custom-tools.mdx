कस्टम tools आपको किसी भी चीज़ को उजागर करने देते हैं जिसे आप स्क्रिप्ट कर सकते हैं (शेल स्क्रिप्ट्स, Node/Bun/Python प्रोग्राम, छोटे binaries) एक tool के रूप में जिसे agent नाम से इनवोक कर सकता है। ये Bolt को आपके प्रोजेक्ट के अपने build, deploy, या डेटा वर्कफ़्लो तक पहुँच देने का सबसे सरल तरीक़ा हैं।

## वे कहाँ रहते हैं

फ़ाइलों को इनमें से किसी एक में ड्रॉप करें:

- `.opencode/tool/` — प्रोजेक्ट-स्कोप्ड, repo के साथ चेक-इन किया गया।
- `.opencode/tools/` — ऊपर वाले के लिए alias के रूप में स्वीकार किया गया।

प्रत्येक फ़ाइल फ़ाइल के नाम पर एक tool बन जाती है (उसके extension को छोड़कर)। Bolt अगली बार शुरू होने पर tools को स्वचालित रूप से उठाता है।

## एक tool की रचना

एक कस्टम tool अपने नाम, विवरण, और input schema को एक header में घोषित करता है, फिर व्यवहार को लागू करता है। सटीक आकार आपके द्वारा चुने गए runtime (शेल स्क्रिप्ट, TypeScript, आदि) पर निर्भर करता है, लेकिन प्रत्येक tool को:

1. अपने inputs के लिए JSON Schema का विज्ञापन करना चाहिए ताकि मॉडल को पता चले कि इसे कैसे कॉल करना है।
2. एक मान (या त्रुटि) लौटानी चाहिए जिसे Bolt TUI में रेंडर कर सके और वापस मॉडल में फ़ीड कर सके।

एक बार लोड होने के बाद, tool `bash` और `grep` जैसे बिल्ट-इन tools के बगल में agent की tool सूची में दिखाई देता है, और उसी [permission](/concepts/permissions) सिस्टम द्वारा गेट किया जाता है।

## कस्टम tool बनाम MCP सर्वर का उपयोग कब करें

- **कस्टम tool** — छोटा, प्रोजेक्ट-विशिष्ट, प्रोजेक्ट्स में कोई पुनरुपयोग नहीं। लिखने में तेज़।
- **MCP सर्वर** — प्रोजेक्ट्स में साझा, या auth के साथ वास्तविक बाहरी सेवा को wrap करता है। देखें [MCP Servers](/extending/mcp-servers)।
- **Plugin tool** — अन्य extension points के साथ npm पैकेज के रूप में वितरित। देखें [Plugins](/extending/plugins)।
