Les variables d'environnement vous permettent de configurer Bolt sans toucher à aucun fichier de configuration — utile dans les pipelines CI, les conteneurs Docker et les environnements partagés où vous ne pouvez pas committer d'identifiants. Elles sont lues une fois au démarrage et ne peuvent pas être modifiées pendant l'exécution de Bolt.

## Référence

| Variable | Description |
| --- | --- |
| `BOLT_LOG_LEVEL` | Définit la verbosité des journaux. Valeurs acceptées : `DEBUG`, `INFO`, `WARN`, `ERROR`. Équivalent à l'option `--log-level`. |
| `BOLT_PRINT_LOGS` | Définir à toute valeur non vide pour afficher la sortie des journaux sur stderr. Équivalent à `--print-logs`. |
| `BOLT_PURE` | Définir à toute valeur non vide pour désactiver tous les plugins externes. Équivalent à `--pure`. |
| `BOLT_SERVER_USERNAME` | Nom d'utilisateur basic auth pour `bolt serve` et `bolt web`. |
| `BOLT_SERVER_PASSWORD` | Mot de passe basic auth pour `bolt serve` et `bolt web`. Tous les clients qui se connectent doivent fournir ce mot de passe. |
| `BOLT_CONFIG` | Remplace le chemin du fichier de configuration que Bolt charge. Bolt ne cherchera pas dans les emplacements par défaut lorsque cette variable est définie. |
| `BOLT_CONFIG_DIR` | Remplace le répertoire de configuration. Bolt cherchera les fichiers de configuration dans ce répertoire au lieu du répertoire de configuration système par défaut. |
| `BOLT_CONFIG_CONTENT` | Fournit toute la configuration sous forme de chaîne JSON en ligne. Utile en CI où l'écriture de fichiers est peu pratique. A la précédence la plus élevée parmi les sources de configuration. |
| `BOLT_GIT_BASH_PATH` | Chemin vers le répertoire `bin` de Git Bash sous Windows, utilisé pour localiser des utilitaires Unix comme `less`. |

## Clés d'API de fournisseurs

Bolt détecte automatiquement les informations d'identification des fournisseurs depuis les variables d'environnement — aucune étape `bolt providers login` requise. Chaque fournisseur recherche une variable d'environnement précise, et Bolt l'utilisera si la variable est définie, indépendamment de ce qui est stocké dans `auth.json`.

<Tip>
  Définissez les clés d'API de fournisseurs dans votre profil de shell (p. ex. `~/.zshrc`, `~/.bashrc`) ou dans un fichier `.env` chargé par votre shell. Vous pouvez aussi les référencer depuis le fichier de configuration en utilisant la syntaxe `${VAR_NAME}` dans un champ `provider.*.apiKey` afin que les clés ne soient jamais stockées en clair.
</Tip>

Variables courantes par fournisseur :

| Variable | Fournisseur |
| --- | --- |
| `ANTHROPIC_API_KEY` | Anthropic (Claude) |
| `OPENAI_API_KEY` | OpenAI (GPT, série o) |
| `GOOGLE_GENERATIVE_AI_API_KEY` | Google (Gemini) |
| `OPENROUTER_API_KEY` | OpenRouter |
| `AWS_ACCESS_KEY_ID` \+ `AWS_SECRET_ACCESS_KEY` | Amazon Bedrock |
| `AZURE_OPENAI_API_KEY` | Azure OpenAI |

Exécutez `bolt models --verbose` pour voir quelle variable d'environnement chaque fournisseur configuré attend.

## Exemples d'utilisation

```bash
# Activer les journaux de débogage pour une seule exécution
BOLT_LOG_LEVEL=DEBUG bolt run "why is the auth test failing?"

# Exécuter sans aucun plugin pour écarter l'interférence de plugins
BOLT_PURE=1 bolt

# Démarrer un serveur public avec basic auth
BOLT_SERVER_USERNAME=team BOLT_SERVER_PASSWORD=mysecret \
  bolt serve --hostname 0.0.0.0 --port 4096

# Fournir la configuration en ligne (utile en CI)
BOLT_CONFIG_CONTENT='{"model":"anthropic/claude-opus-4-5"}' \
  ANTHROPIC_API_KEY=sk-ant-xxx \
  bolt run "generate a changelog for this release"
```
