يمكن لوكلاء Bolt قراءة الملفات وكتابتها وتشغيل أوامر الصدفة. تُضبط هذه القوة عبر طبقتين: مستوى وصول لكل وكيل، وموجّهات أذونات تفاعلية يمكنك الموافقة عليها أو رفضها أو ضبطها مسبقًا.

## مستويات وصول الوكلاء

لكل وكيل مدمج مستوى وصول معلن:

| مستوى الوصول | قراءة الملفات | كتابة الملفات | تشغيل أوامر الصدفة |
| --- | --- | --- | --- |
| **كامل** | ✓ | ✓ | ✓ |
| **تحرير** | ✓ | ✓ | ✗ |
| **قراءة** | ✓ | ✗ | ✗ |

الإسنادات المدمجة:

- **كامل** — `code`، `debug`، `refactor`، `migrate`، `perf`
- **تحرير** — `docs`
- **قراءة** — `plan`، `ask`، `code-review`، `security`

بدّل بين الوكلاء بـ `Tab` في الـ TUI، أو مرّر `--agent <name>` إلى `bolt run`.

## الموجّهات التفاعلية

ضمن مستوى وصول الوكيل، تطلب الإجراءات التي قد تكون مدمّرة تأكيدًا. يمكنك الموافقة مرة واحدة، أو الموافقة للجلسة كاملة، أو الرفض. تُعيد الاستدعاءات المرفوضة خطأ للوكيل ويتابع العمل.

## الموافقة غير التفاعلية

في CI أو السكربتات أو سير العمل المحلي الموثوق، يدعم `bolt run` خيارات تتجاوز الموجّهات:

```bash
bolt run --auto "tidy up imports"                   # auto-approve anything not explicitly denied
bolt run --yolo "tidy up imports"                   # alias for --auto
bolt run --dangerously-skip-permissions "..."       # bypass every prompt
```

<Warning>
  تتيح `--auto` و`--yolo` و`--dangerously-skip-permissions` للوكيل القراءة والكتابة والتنفيذ دون السؤال. استخدمها فقط في البيئات الموثوقة.
</Warning>

## قواعد على مستوى الإعدادات

يمكنك رفض (أو السماح مسبقًا بـ) أدوات معيّنة للمشروع بأكمله بإضافة كتلة `permission` إلى `.bolt/bolt.jsonc`. تنطبق على كل جلسة في المشروع، بما في ذلك استدعاءات `bolt run` غير التفاعلية. راجع [الإعدادات](/concepts/configuration) للمخطط.
