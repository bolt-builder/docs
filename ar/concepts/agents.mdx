يعامل Bolt كل شخصية ذكاء اصطناعي كـ **وكيل** مُسمّى: موجّه نظام مقرون بمجموعة أذونات أدوات محدّدة بدقة. بدلًا من تشغيل نموذج واحد للأغراض العامة لكل مهمة، تختار الوكيل الذي يطابق وصوله وتركيزه ما تحتاجه — سواء كان تدقيقًا أمنيًا، أو كتابة وثائق، أو تجهيز ترحيل كامل لإطار عمل.

## مستويات الوصول

كل وكيل مدمج يُعيَّن له أحد ثلاثة مستويات وصول تحدّد الأدوات التي يمكنه استدعاؤها:

| المستوى | الأذونات الممنوحة | الاستخدام المعتاد |
|-------|---------------------|-------------|
| **كامل** | قراءة الملفات، كتابتها/تحريرها، تشغيل أوامر الصدفة | البرمجة الفعلية، التصحيح، إعادة الهيكلة، الترحيل |
| **تحرير** | قراءة الملفات، كتابتها/تحريرها — بدون صدفة | التوثيق، تحديث التعليقات، تعديلات نصية آمنة |
| **قراءة** | قراءة الملفات فقط — بدون كتابة أو صدفة | التخطيط، البحث، مراجعة الشيفرة، التدقيق |

## الوكلاء المدمجون

يأتي Bolt مع عشرة وكلاء متخصصين جاهزين. بدّل بينهم في الـ TUI بضغط <kbd>Tab</kbd>.

| الوكيل | الوصول | الوصف |
|-------|--------|-------------|
| `code` | كامل | الافتراضي: يقرأ ويكتب ويشغّل الشيفرة |
| `plan` | قراءة | يستكشف قاعدة الشيفرة وينتج خطة دون تغيير الشيفرة |
| `ask` | قراءة | أسئلة وبحث — بدون تعديل الملفات |
| `code-review` | قراءة | يراجع التغييرات بحثًا عن الصحة والأسلوب والأمان |
| `debug` | كامل | يصحّح الاختبارات الفاشلة والانهيارات وأخطاء المنطق |
| `refactor` | كامل | إعادة هيكلة آمنة مع التحقق من الاختبارات في كل خطوة |
| `docs` | تحرير | يكتب ويحدّث الوثائق والتعليقات |
| `security` | قراءة | تدقيق أمني: ثغرات، أسرار، أنماط خطرة |
| `migrate` | كامل | ترقيات إطارات العمل وترحيل الاعتماديات |
| `perf` | كامل | تحليل الأداء والتحسين |

## الوكلاء الفرعيون

بالإضافة إلى الوكلاء العشرة الأساسيين، يعرض Bolt **وكيلين فرعيين** مدمجين يمكن للوكلاء الأساسيين تفويض العمل إليهما أثناء الجلسة. لا تختار الوكيل الفرعي يدويًا أبدًا — يُستدعى تلقائيًا عندما يقرّر وكيل أساسي إطلاقه.

| الوكيل الفرعي | الدور |
|----------|------|
| `@general` | تفويض مهام معقّدة متعدّدة الخطوات تتطلّب قدرات واسعة |
| `@explore` | بحث سريع للقراءة فقط في قاعدة الشيفرة — يجتاز الملفات دون آثار جانبية |

<Tip>
  عندما تحتاج إلى فهم قاعدة شيفرة غير مألوفة بسرعة، ابدأ بالوكيل `ask` أو `plan`. خلف الكواليس يمكنهما إطلاق الوكيل الفرعي `@explore` لفهرسة مشروعك بسرعة عالية قبل إنتاج إجابة — دون لمس أي ملف.
</Tip>

## التبديل بين الوكلاء

**في الـ TUI** — اضغط <kbd>Tab</kbd> للتنقّل بين قائمة الوكلاء المتاحين في أي وقت أثناء الجلسة. يظهر الوكيل النشط في تذييل الجلسة.

**بشكل غير تفاعلي** — مرّر `--agent <name>` إلى `bolt run` لتثبيت وكيل محدّد طوال هذه التشغيلة:

```bash
bolt run --agent ask "what does the authentication flow do?"
bolt run --agent security "audit the API layer for injection vulnerabilities"
bolt run --agent docs "add JSDoc comments to every exported function in src/utils"
```

## سرد الوكلاء

لعرض جميع الوكلاء المتاحين — المدمجين والمخصّصين — مع أوضاعهم وإعدادات أذوناتهم:

```bash
bolt agent list
```

## الوكلاء المخصّصون

يمكنك إنشاء وكلائك الخاصّين بطريقتين.

### التوليد باستخدام `bolt agent create`

يولّد المعالج التفاعلي ملف وكيل باستخدام LLM ويكتبه على القرص:

```bash
bolt agent create
```

جميع الخيارات اختيارية. مرّرها للتشغيل بشكل غير تفاعلي:

```bash
bolt agent create \
  --description "Audit GraphQL resolvers for N+1 problems and suggest DataLoader fixes" \
  --path .bolt/agents \
  --mode primary \
  --permissions read,grep,glob \
  --model anthropic/claude-opus-4-5
```

| الخيار | الوصف |
|------|-------------|
| `--description` | ما الذي يجب أن يفعله الوكيل (يُستخدم كموجّه LLM للتوليد) |
| `--path` | المجلد الذي يُكتب فيه ملف الوكيل المولّد |
| `--mode` | `all` (الافتراضي) أو `primary` أو `subagent` |
| `--permissions` | قائمة أذونات مفصولة بفواصل يُسمح بها. اتركه فارغًا لجميع الأذونات. |
| `--model` / `-m` | النموذج المستخدم بتنسيق `provider/model` |

### كتابة ملف markdown يدويًا

الوكيل هو ملف markdown ذو بيانات وصفية YAML. ضعه في `.bolt/agents/` داخل مشروعك أو في مجلد الوكلاء العام:

```markdown
---
description: "Audit GraphQL resolvers for N+1 problems"
mode: primary
permission:
  bash: deny
  edit: deny
---

You are a GraphQL performance specialist. Your job is to identify N+1 query
patterns in resolver code and recommend DataLoader-based solutions...
```

يصبح اسم الملف (بدون `.md`) هو معرّف الوكيل.

### الأذونات المتاحة

الأذونات هي بوابات الأدوات الدقيقة التي تتحكم فيها عند إنشاء وكيل مخصّص:

| الإذن | يتحكم في |
|------------|----------|
| `bash` | تنفيذ أوامر الصدفة |
| `read` | قراءة الملفات |
| `edit` | كتابة الملفات وتحريرها (يضبط أيضًا `write` و`apply_patch`) |
| `glob` | سرد الملفات/المجلدات عبر glob |
| `grep` | البحث في الملفات عبر ripgrep |
| `webfetch` | جلب HTTP من الويب |
| `task` | إطلاق مهام الوكيل الفرعي |
| `todowrite` | إنشاء وتحديث بنود المهام |
| `websearch` | استعلامات البحث على الويب |
| `lsp` | عمليات بروتوكول خادم اللغة |
| `skill` | الوصول إلى مهارات المشروع |
