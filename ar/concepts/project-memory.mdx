ذاكرة المشروع هي ما يجعل Bolt يبدو وكأنه يعرف مشروعك بالفعل. عندما ينهي الجلسة دورها، يستخرج Bolt ما كان مفيدًا ويكتبه إلى مخزن ذاكرة خاص بكل مشروع. عند فتح جلسة جديدة، يحقن Bolt فهرس الذاكرة بالإضافة إلى آخر ملخّص للجلسة في موجّه النظام حتى يبدأ الوكيل بسياق حقيقي بدلًا من صفحة بيضاء.

## كيف يعمل الالتقاط

في ختام كل دور محادثة، يطلب Bolt من النموذج تلخيص الحقائق الدائمة التي ستكون مفيدة في المرة القادمة: الاصطلاحات، ملاحظات البنية، تخطيط الملفات، أوامر البناء/الاختبار، النقاط الحرجة، والخيوط المفتوحة. تُكتب هذه إلى القرص تحت مجلد ذاكرة المشروع، بجانب ملخّص متجدّد لأحدث جلسة.

الذاكرة لكل مشروع. تتشارك نسختان من نفس المستودع على نفس الجهاز الذاكرة؛ لا ترى المشاريع غير المرتبطة ذاكرة بعضها البعض أبدًا.

## أدوات صريحة

يمكن للوكلاء أيضًا قراءة الذاكرة وكتابتها مباشرة أثناء الجلسة:

- `memory_save` — تسجيل حقيقة معيّنة يجب على الوكيل تذكّرها في المرة القادمة.
- `memory_recall` — البحث عن شيء التقطه الوكيل (أو أنت) سابقًا.

يمكنك أن تطلب من الوكيل "تذكّر أننا نستخدم pnpm وليس npm" وسيستدعي `memory_save` نيابة عنك.

## عناصر تحكم لكل جلسة

داخل الـ TUI يمكنك تبديل سلوك الذاكرة للجلسة الحالية عبر أوامر slash:

```text
/memory use on|off         # whether this session reads project memory
/memory contribute on|off  # whether this session writes back to memory
```

هذا مفيد عندما تريد جلسة استكشافية مؤقتة لا تلوّث ذاكرتك، أو جلسة للقراءة فقط تستفيد من السياق السابق.

## فحص وتحرير الذاكرة

```bash
bolt memory           # inspect the memory store for the current project
```

تُخزَّن الذاكرة كملفات نصية عادية على القرص تحت مجلد بيانات Bolt الخاص بالمشروع، فيمكنك grep أو تحرير أو حذف المدخلات مباشرة. للعثور على المسار الدقيق على جهازك، شغّل `bolt debug paths`.
