Bolt постачається з чотирма командами, які підключають ваш щоденний Git-процес до AI: агент GitHub Actions, який ви можете встановити однією командою, ярлик для отримання pull request-ів, AI-генератор повідомлень комітів та AI-ревʼюер коду з машинозчитуваними кодами виходу. Разом вони дозволяють вам залучати Bolt на кожному етапі розробки — локальне програмування, ревʼю PR та безперервна інтеграція.

## `bolt github`

Керує агентом GitHub Actions, що запускає Bolt на подіях CI.

### `bolt github install`

Встановлює робочий процес GitHub Actions у поточний репозиторій. Це записує YAML робочого процесу в `.github/workflows/`, щоб Bolt автоматично запускався на коментарях issue, нових pull request-ах або інших подіях, які ви налаштуєте.

```bash
bolt github install
```

Запускайте це з кореня git-репозиторію. Вам знадобиться доступ на запис до `.github/workflows/`.

### `bolt github run`

Запускає GitHub-агента локально або всередині кроку CI, відтворюючи конкретне корисне навантаження події GitHub.

```bash
bolt github run --event <event> --token <pat>
```

| Прапорець | Опис |
|------|-------------|
| `--event <event>` | Ім'я події GitHub або шлях до JSON-навантаження події |
| `--token <pat>` | Особистий токен доступу GitHub (`github_pat_…`), що використовується для публікації коментарів та отримання контексту |

## Налаштування агента GitHub Actions

<Steps>
  <Step title="Встановіть робочий процес">
    З кореня вашого репозиторію:

    ```bash
    bolt github install
    ```

    Bolt записує файл робочого процесу GitHub Actions у `.github/workflows/`. Закомітьте та запуште файл.
  </Step>

  <Step title="Додайте свій API-ключ як секрет">
    У налаштуваннях вашого репозиторію додайте API-ключ вашого улюбленого LLM-провайдера як секрет репозиторію (наприклад, `ANTHROPIC_API_KEY`). Робочий процес підхопить його автоматично.
  </Step>

  <Step title="Запустіть агента">
    Прокоментуйте `/bolt <your request>` у будь-якому issue чи pull request. Робочий процес запускається, Bolt читає корисне навантаження події й публікує відповідь із результатом.
  </Step>

  <Step title="Запустіть локально для налагодження">
    Відтворіть живе корисне навантаження події з попереднього запуску робочого процесу:

    ```bash
    bolt github run \
      --event path/to/event.json \
      --token github_pat_abc123
    ```
  </Step>
</Steps>

## `bolt pr <number>`

Отримує pull request GitHub у локальну гілку та запускає Bolt у цій гілці — готовий до ревʼю, налагодження чи продовження роботи з того місця, де зупинився автор PR.

```bash
bolt pr 42
```

Bolt використовує CLI `gh` для отримання PR, створює гілку з ім'ям `pr/<number>` і налаштовує upstream-ref для відстеження. Для крос-репозиторійних (fork) PR він автоматично додає fork як віддалений. Якщо опис PR містить URL спільного доступу до сесії Bolt (`opncd.ai/s/…`), сесія імпортується, тож ви можете продовжити розмову автора.

> Потребує встановленого та автентифікованого [GitHub CLI (`gh`)](https://cli.github.com/).

## `bolt commit`

Генерує повідомлення коміту з ваших проіндексованих (або всіх відстежуваних) змін і комітить одним кроком.

```bash
bolt commit
```

Bolt робить diff ваших змін, передає diff агенту `commit` разом із нещодавніми темами комітів для довідки стилю та виконує `git commit -m <message>` з результатом.

### Прапорці

| Прапорець | Псевдонім | Опис |
|------|-------|-------------|
| `--all` | `-a` | Комітити всі відстежувані зміни, а не лише проіндексовані (еквівалент `git commit -a`) |
| `--dry-run` | | Друкувати згенероване повідомлення без коміту |
| `--model <provider/model>` | `-m` | Перевизначити модель, що використовується для генерації повідомлення |

```bash
# Stage everything and commit
bolt commit --all

# Preview the message without committing
bolt commit --dry-run

# Use a specific model
bolt commit --model anthropic/claude-opus-4-5
```

<Tip>
  Використовуйте `bolt commit --dry-run`, щоб побачити згенероване повідомлення перед комітом. Якщо хочете відредагувати, скопіюйте вивід і запустіть `git commit -m "…"` зі своїми правками.
</Tip>

## `bolt review`

Запускає агента `code-review` проти diff і виходить із машинозчитуваним вердиктом. Останній рядок ревʼю завжди — або `Verdict: PASS`, або `Verdict: FAIL`, що робить `bolt review` готовим для CI-конвеєрів.

```bash
bolt review
```

За замовчуванням `bolt review` робить diff `HEAD` проти робочого дерева. Використовуйте прапорці нижче, щоб обмежити diff.

### Прапорці

| Прапорець | Псевдонім | Опис |
|------|-------|-------------|
| `--staged` | | Переглядати лише проіндексовані зміни |
| `--branch <name>` | | Переглядати зміни з моменту merge base із названою гілкою (за замовчуванням — гілка репозиторію за замовчуванням) |
| `--model <provider/model>` | `-m` | Модель для використання у ревʼю |

### Коди виходу

| Код | Значення |
|------|---------|
| `0` | `Verdict: PASS` — без критичних чи основних проблем |
| `1` | `Verdict: FAIL` — знайдено одну чи більше критичних чи основних проблем |
| `2` | Вердикт не вдалося визначити з відповіді |

### Використання у робочому процесі GitHub Actions

```yaml
name: AI Code Review
on:
  pull_request:
    branches: [main]

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Install Bolt
        run: curl -fsSL https://raw.githubusercontent.com/bolt-builder/bolt-cli/dev/install | bash

      - name: AI review
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: bolt review --branch main
```

Ненульовий код виходу провалює перевірку, блокуючи злиття, доки проблеми не буде вирішено.

<Tip>
  Запускайте `bolt review --staged` перед комітом, щоб виявити проблеми, поки їх легко змінити — до того, як вони потраплять до pull request.
</Tip>
