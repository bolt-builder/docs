Bolt використовує шарувату систему конфігурації: **глобальний** файл конфігурації для налаштувань за замовчуванням користувача та **проєктний** файл конфігурації для налаштувань, специфічних для репозиторію. Обидва файли використовують формат JSONC (JSON із коментарями), і обидва автоматично створюються з покажчиком `$schema`, який вмикає автозаповнення в редакторі.

## Розташування файлів конфігурації

### Проєктна конфігурація

Створюється автоматично під час першого запуску всередині вашого проєкту:

```text
<project-root>/.bolt/bolt.jsonc
```

Комітьте цей файл, щоб ділитися конфігурацією провайдерів, MCP-серверами та власними інструкціями з рештою команди. Чутливі облікові дані ніколи не повинні потрапляти сюди — натомість використовуйте змінні середовища або глобальну конфігурацію.

### Глобальна конфігурація

Застосовується до всіх проєктів на вашому комп'ютері. Bolt шукає перший відповідний файл у каталозі конфігурації ОС:

```text
# macOS / Linux
~/.config/bolt/bolt.jsonc   (preferred)
~/.config/bolt/bolt.json

# Windows
%APPDATA%\bolt\bolt.jsonc
%APPDATA%\bolt\bolt.json
```

<Accordion title="Де знаходиться глобальний каталог конфігурації?">
  Bolt дотримується специфікації XDG Base Directory на Linux і macOS (`~/.config/bolt/`) та `%APPDATA%\bolt\` на Windows. Запустіть `bolt debug config` для виведення повної розв'язаної конфігурації на вашому комп'ютері.
</Accordion>

## Мінімальний приклад конфігурації

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    // Provider config goes here
  }
}
```

Поле `$schema` вмикає IntelliSense та валідацію в редакторах, що підтримують JSON Schema. Bolt автоматично записує це поле, якщо його бракує.

## Довідник конфігурації

### `provider`

Налаштуйте специфічні для провайдера параметри, такі як власні базові URL, налаштування регіону або іменовані облікові дані:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "anthropic": {
      "name": "Anthropic"
    },
    "amazon-bedrock": {
      "options": {
        "region": "us-east-1"
      }
    }
  }
}
```

### `mcp`

Реєструйте сервери [Model Context Protocol](https://modelcontextprotocol.io), які агент може викликати як інструменти:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "my-server": {
      "type": "local",
      "command": "node",
      "args": ["./mcp-server.js"],
      "env": {
        "DATABASE_URL": "$DATABASE_URL"
      }
    }
  }
}
```

Керуйте MCP-серверами інтерактивно за допомогою `bolt mcp add`, `bolt mcp list`, `bolt mcp auth` та `bolt mcp debug`.

### `instructions`

Додавайте власні системні інструкції, які додаються в кожну сесію. Корисно для дотримання угод з кодування, стайлґайдів або специфічних для проєкту правил:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": [
    "Always write tests alongside new code.",
    "Follow the Google TypeScript Style Guide.",
    "Never introduce new dependencies without explaining the trade-off."
  ]
}
```

Інструкції з кількох файлів конфігурації (глобальний \+ проєктний) автоматично об'єднуються та дедуплікуються.

### `plugin`

Завантажуйте плагіни Bolt. Плагіни можуть додавати нові інструменти, провайдерів, джерела контексту та хуки:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": [
    "./plugins/my-tool.ts",
    "@my-org/bolt-plugin-jira"
  ]
}
```

### Віддалена конфігурація через `url`

Отримуйте конфігурацію з віддаленої URL-адреси під час запуску. Корисно для централізованої командної конфігурації:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "url": "https://config.example.com/bolt-team.json",
  "headers": {
    "Authorization": "Bearer $TEAM_CONFIG_TOKEN"
  }
}
```

## Підстановка змінних

Значення конфігурації можуть посилатися на змінні середовища за допомогою синтаксису `$VAR_NAME` або `${VAR_NAME}`. Підстановка відбувається під час завантаження, до розбору конфігурації:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "database-tools": {
      "type": "local",
      "command": "npx",
      "args": ["db-mcp-server"],
      "env": {
        "DATABASE_URL": "$DATABASE_URL",
        "API_KEY": "${INTERNAL_API_KEY}"
      }
    }
  }
}
```

<Accordion title="Як використовувати змінні середовища в конфігурації?">
  Посилайтеся на будь-яку змінну середовища за допомогою `$VAR_NAME` або `${VAR_NAME}` будь-де у рядковому значенні конфігурації. Bolt підставляє значення під час завантаження. Якщо змінна не встановлена, використовується літеральний рядок `$VAR_NAME` — Bolt не виходить із ладу мовчки і не викидає помилку при відсутній підстановці.
</Accordion>

## Перевизначення через змінні середовища

Ці змінні середовища дозволяють перенаправити або повністю перевизначити конфігурацію, що корисно для CI, контейнерів і тестування:

| Змінна | Опис |
| --- | --- |
| `BOLT_CONFIG` | Абсолютний шлях до файлу конфігурації для завантаження замість проєктного |
| `BOLT_CONFIG_DIR` | Перевизначає каталог, у якому Bolt шукає файли конфігурації |
| `BOLT_CONFIG_CONTENT` | Надає вміст сирої JSONC-конфігурації як рядок — файл не потрібен |

`BOLT_CONFIG_CONTENT` особливо зручний у контейнеризованих середовищах, де монтування файлу незручне:

```bash
export BOLT_CONFIG_CONTENT='{"provider":{"anthropic":{}}}'
bolt run "summarise the codebase"
```

<Accordion title="Яка конфігурація має пріоритет, коли активно декілька джерел?">
  Bolt об'єднує конфігурації в такому порядку (пізніші записи виграють):

  1. Файл глобальної конфігурації (`bolt.jsonc` / `bolt.json` у каталозі конфігурації ОС)
  2. Віддалені конфігурації, отримані з записів `url` у глобальній конфігурації
  3. Файли проєктної конфігурації (`.bolt/bolt.jsonc`, `.bolt/bolt.json`)
  4. Файл `BOLT_CONFIG` (якщо встановлено)
  5. `BOLT_CONFIG_CONTENT` (якщо встановлено)

  Поля-масиви, такі як `instructions`, конкатенуються між джерелами, а не замінюються. Поля-об'єкти глибоко об'єднуються з переможцями пізніх значень у конфліктах.
</Accordion>
