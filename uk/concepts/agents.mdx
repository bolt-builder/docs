Bolt розглядає кожну AI-персону як іменований **агент**: системний промпт у поєднанні з точно визначеним набором дозволів на інструменти. Замість того щоб запускати одну універсальну модель для кожного завдання, ви обираєте того агента, чий доступ і фокус відповідає тому, що вам потрібно — чи то аудит безпеки, написання документації, чи налаштування повної міграції фреймворку.

## Рівні доступу

Кожен вбудований агент отримує один з трьох рівнів доступу, які визначають, які інструменти він може викликати:

| Рівень | Надані дозволи | Типове використання |
|-------|---------------------|-------------|
| **Full** | Читання файлів, запис/редагування файлів, виконання shell-команд | Активне кодування, налагодження, рефакторинг, міграції |
| **Edit** | Читання файлів, запис/редагування файлів — без shell | Документація, оновлення коментарів, безпечне редагування прози |
| **Read** | Лише читання файлів — без запису, без shell | Планування, дослідження, ревʼю коду, аудити |

## Вбудовані агенти

Bolt постачається з десятьма спеціалізованими агентами. Перемикайтеся між ними в TUI, натискаючи <kbd>Tab</kbd>.

| Агент | Доступ | Опис |
|-------|--------|-------------|
| `code` | Full | За замовчуванням: читає, пише та виконує код |
| `plan` | Read | Досліджує кодову базу та створює план без змін коду |
| `ask` | Read | Питання та дослідження — без редагування файлів |
| `code-review` | Read | Переглядає зміни на предмет коректності, стилю та безпеки |
| `debug` | Full | Налагоджує невдалі тести, збої та логічні помилки |
| `refactor` | Full | Безпечний рефакторинг з перевіркою тестів на кожному кроці |
| `docs` | Edit | Пише та оновлює документацію та коментарі |
| `security` | Read | Аудит безпеки: вразливості, секрети та небезпечні патерни |
| `migrate` | Full | Оновлення фреймворків і міграції залежностей |
| `perf` | Full | Аналіз продуктивності та оптимізація |

## Субагенти

Окрім десяти основних агентів, Bolt надає двох вбудованих **субагентів**, яким основні агенти можуть делегувати роботу під час сесії. Ви ніколи не обираєте субагента вручну — вони диспетчеризуються автоматично, коли основний агент вирішує запустити одного з них.

| Субагент | Роль |
|----------|------|
| `@general` | Делегування комплексних багатоетапних завдань, що вимагають широких можливостей |
| `@explore` | Швидке дослідження кодової бази лише для читання — переглядає файли без побічних ефектів |

<Tip>
  Коли вам потрібно швидко зрозуміти незнайому кодову базу, почніть з агента `ask` або `plan`. За лаштунками вони можуть диспетчеризувати субагента `@explore` для швидкої індексації вашого проєкту перед формуванням відповіді — не торкаючись жодного файлу.
</Tip>

## Перемикання агентів

**У TUI** — натискайте <kbd>Tab</kbd> для циклічного переходу за списком доступних агентів у будь-який момент під час сесії. Активний агент показано у футері сесії.

**Неінтерактивно** — передайте `--agent <name>` у `bolt run`, щоб закріпити конкретного агента на час цього запуску:

```bash
bolt run --agent ask "what does the authentication flow do?"
bolt run --agent security "audit the API layer for injection vulnerabilities"
bolt run --agent docs "add JSDoc comments to every exported function in src/utils"
```

## Список агентів

Щоб побачити всіх доступних агентів — як вбудованих, так і власних — з їх режимами та налаштуваннями дозволів:

```bash
bolt agent list
```

## Власні агенти

Ви можете створювати власних агентів двома способами.

### Генерація за допомогою `bolt agent create`

Інтерактивний майстер генерує файл агента за допомогою LLM і записує його на диск:

```bash
bolt agent create
```

Усі прапорці необовʼязкові. Передайте їх, щоб запустити неінтерактивно:

```bash
bolt agent create \
  --description "Audit GraphQL resolvers for N+1 problems and suggest DataLoader fixes" \
  --path .bolt/agents \
  --mode primary \
  --permissions read,grep,glob \
  --model anthropic/claude-opus-4-5
```

| Прапорець | Опис |
|------|-------------|
| `--description` | Що агент повинен робити (використовується як промпт для LLM під час генерації) |
| `--path` | Каталог, у який записати згенерований файл агента |
| `--mode` | `all` (за замовчуванням), `primary` або `subagent` |
| `--permissions` | Список дозволів через кому. Пропустіть для всіх. |
| `--model` / `-m` | Модель для використання у форматі `provider/model` |

### Ручне написання markdown-файлу

Агент — це просто markdown-файл із YAML frontmatter. Розмістіть його в `.bolt/agents/` всередині проєкту або в глобальному каталозі агентів:

```markdown
---
description: "Audit GraphQL resolvers for N+1 problems"
mode: primary
permission:
  bash: deny
  edit: deny
---

You are a GraphQL performance specialist. Your job is to identify N+1 query
patterns in resolver code and recommend DataLoader-based solutions...
```

Імʼя файлу (без `.md`) стає ідентифікатором агента.

### Доступні дозволи

Дозволи — це тонко-гранульовані шлюзи інструментів, якими ви керуєте під час створення власного агента:

| Дозвіл | Керує |
|------------|----------|
| `bash` | Виконанням shell-команд |
| `read` | Читанням файлів |
| `edit` | Записом і редагуванням файлів (також керує `write` і `apply_patch`) |
| `glob` | Пошуком файлів через glob/переглядом каталогів |
| `grep` | Пошуком файлів через ripgrep |
| `webfetch` | HTTP-запитами до вебу |
| `task` | Запуском завдань субагентів |
| `todowrite` | Створенням і оновленням елементів todo |
| `websearch` | Запитами веб-пошуку |
| `lsp` | Операціями протоколу мовного сервера |
| `skill` | Доступом до навичок проєкту |
