Пам'ять проєкту — це те, що змушує Bolt почуватися так, ніби він уже знає ваш проєкт. Коли сесія завершує свій хід, Bolt дистилює те, що було корисним, і записує це у сховище пам'яті проєкту. Коли ви відкриваєте нову сесію, Bolt додає індекс пам'яті плюс останній дайджест сесії до системного промпту, щоб агент починав з реальним контекстом, а не з чистого аркуша.

## Як працює захоплення

Наприкінці кожного розмовного ходу Bolt просить модель узагальнити довговічні факти, які будуть корисні наступного разу: угоди, архітектурні нотатки, розкладку файлів, команди збірки/тестів, підводні камені та відкриті питання. Вони записуються на диск у каталозі пам'яті проєкту разом із перекочуваним дайджестом останньої сесії.

Пам'ять — на проєкт. Дві копії одного репозиторію на одному комп'ютері поділяють пам'ять; не пов'язані проєкти ніколи не бачать пам'яті один одного.

## Явні інструменти

Агенти також можуть напряму читати та записувати пам'ять під час сесії:

- `memory_save` — записати конкретний факт, який агент повинен пам'ятати наступного разу.
- `memory_recall` — знайти те, що агент (або ви) захопили раніше.

Ви можете попросити агента «запам'ятати, що ми використовуємо pnpm, а не npm», і він викличе `memory_save` за вас.

## Керування для окремих сесій

У TUI ви можете перемикати поведінку пам'яті для поточної сесії за допомогою slash-команд:

```text
/memory use on|off         # whether this session reads project memory
/memory contribute on|off  # whether this session writes back to memory
```

Це корисно, коли ви хочете одноразову дослідницьку сесію, яка не забруднить вашу пам'ять, або сесію лише для читання, яка все ж отримує вигоду з попереднього контексту.

## Перегляд і редагування пам'яті

```bash
bolt memory           # inspect the memory store for the current project
```

Пам'ять зберігається як звичайні файли на диску в каталозі даних Bolt проєкту, тож ви можете напряму робити grep, редагувати або видаляти записи. Щоб знайти точний шлях на вашому комп'ютері, запустіть `bolt debug paths`.
