Агенти Bolt можуть читати файли, записувати файли та виконувати shell-команди. Ця сила обмежується двома шарами: рівнем доступу для окремого агента та інтерактивними запитами дозволу, які ви можете схвалити, відхилити або налаштувати заздалегідь.

## Рівні доступу агентів

Кожен вбудований агент має задекларований рівень доступу:

| Рівень доступу | Читання файлів | Запис файлів | Виконання shell-команд |
| --- | --- | --- | --- |
| **Full** | ✓ | ✓ | ✓ |
| **Edit** | ✓ | ✓ | ✗ |
| **Read** | ✓ | ✗ | ✗ |

Вбудовані відповідності:

- **Full** — `code`, `debug`, `refactor`, `migrate`, `perf`
- **Edit** — `docs`
- **Read** — `plan`, `ask`, `code-review`, `security`

Перемикайте агентів клавішею `Tab` у TUI або передавайте `--agent <name>` до `bolt run`.

## Інтерактивні запити

У межах рівня доступу агента потенційно руйнівні дії все одно запитують підтвердження. Ви можете схвалити один раз, схвалити на сесію або відхилити. Відхилені виклики повертають помилку агенту, і він продовжує роботу.

## Неінтерактивне схвалення

Для CI, скриптів або довірених локальних робочих процесів `bolt run` підтримує прапорці, що пропускають запити:

```bash
bolt run --auto "tidy up imports"                   # auto-approve anything not explicitly denied
bolt run --yolo "tidy up imports"                   # alias for --auto
bolt run --dangerously-skip-permissions "..."       # bypass every prompt
```

<Warning>
  `--auto`, `--yolo` та `--dangerously-skip-permissions` дозволяють агенту читати, записувати та виконувати без запитів. Використовуйте їх лише в довірених середовищах.
</Warning>

## Правила на рівні конфігурації

Ви можете попередньо відхилити (або попередньо дозволити) конкретні інструменти для всього проєкту, додавши блок `permission` до `.bolt/bolt.jsonc`. Це застосовується до кожної сесії в проєкті, включно з неінтерактивними викликами `bolt run`. Див. [Конфігурацію](/concepts/configuration) для схеми.
