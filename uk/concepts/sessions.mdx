**Сесія** — це основна одиниця роботи Bolt. Кожен промпт, який ви надсилаєте, кожен файл, який агент читає чи редагує, і кожен виклик інструменту, який робить модель, стійко записуються в історії цієї сесії. Оскільки сесії живуть у локальній базі даних SQLite, вони переживають перезапуски процесу, їх можна перелічувати та запитувати в будь-який час, і вони ніколи не залишають ваш комп'ютер, якщо ви явно не поділитеся ними чи не експортуєте.

<Note>
  Усі дані сесій зберігаються локально в базі даних SQLite на вашому власному комп'ютері. Нічого не надсилається на зовнішні сервери, якщо ви не увімкнете спільний доступ. Використовуйте `bolt db path`, щоб знайти точний файл бази даних.
</Note>

## Життєвий цикл сесії

Сесія починається у момент, коли ви надсилаєте перший промпт, і закінчується лише коли ви її видалите. Між цими двома точками ви можете вільно від'єднуватися, відновлювати, розгалужувати або передавати її.

<Steps>
  <Step title="Створіть або продовжте сесію">
    Запустіть TUI, щоб інтерактивно почати нову сесію, або передайте промпт у `bolt run`, щоб створити її неінтерактивно:

    ```bash
    # New session in the TUI
    bolt

    # New session non-interactively
    bolt run "add error handling to the payment service"
    ```
  </Step>
  <Step title="Від'єднайтеся та поверніться пізніше">
    Закрийте TUI будь-коли — сесія зберігається автоматично. Відновіть останню сесію за допомогою `--continue` або націльтеся на конкретну сесію за ID з `--session`:

    ```bash
    # Resume the most recent session
    bolt run --continue "now write the tests too"

    # Resume a specific session
    bolt run --session ses_abc123 "continue from where we left off"
    ```
  </Step>
  <Step title="Розгалужуйте перед експериментами">
    Використовуйте `--fork`, щоб розгалужитися від поточної історії сесії перед ризикованою зміною. Форк — це незалежна сесія, яка не впливає на оригінал:

    ```bash
    bolt run --continue --fork "try rewriting this with a functional approach"
    ```
  </Step>
  <Step title="Діліться та співпрацюйте">
    Згенеруйте URL спільного доступу за допомогою `--share`. Будь-хто з посиланням може переглянути стенограму сесії в браузері:

    ```bash
    bolt run --share --continue "final pass — clean up the diff"
    ```
  </Step>
</Steps>

## Команди керування сесіями

### Перегляд сесій

```bash
bolt session list
```

Виводить відформатовану таблицю всіх сесій з їх ID, заголовком і часом останнього оновлення. Додайте `--format json`, щоб отримати вивід, придатний для машинного читання, або `-n <N>`, щоб обмежити останніми N сесіями:

```bash
bolt session list --format json
bolt session list -n 10
```

### Видалення сесії

```bash
bolt session delete <sessionID>
```

Назавжди видаляє сесію та всі її повідомлення з локальної бази даних.

## Прапорці run для керування сесіями

Ці прапорці доступні у `bolt run`:

| Прапорець | Псевдонім | Опис |
|------|-------|-------------|
| `--continue` | `-c` | Продовжити останню сесію |
| `--session <id>` | `-s` | Продовжити конкретну сесію за ID |
| `--fork` | | Розгалужити сесію перед продовженням (потребує `--continue` або `--session`) |
| `--share` | | Згенерувати URL спільного доступу для сесії |
| `--title <title>` | | Встановити або перевизначити заголовок сесії |

## Експорт сесій

Експортуйте повну стенограму сесії як JSON:

```bash
# Export the most recent session
bolt export

# Export a specific session
bolt export <sessionID>

# Export with sensitive data redacted
bolt export --sanitize > transcript.json
```

Прапорець `--sanitize` замінює шляхи до файлів, вміст коду, входи та виходи інструментів та інші потенційно чутливі поля на заповнювачі `[redacted:kind:id]` — корисно для обміну стенограмами з колегами або створення звітів про помилки.

## Імпорт сесій

Імпортуйте сесію з локального JSON-файлу або напряму з URL спільного доступу:

```bash
# From a local file
bolt import ./transcript.json

# From a share URL
bolt import https://opncd.ai/share/abc123
```

Імпортовані сесії з'являються у вашому локальному списку сесій і повністю відновлюються.

## Запити до бази даних сесій

Bolt надає базову базу даних SQLite напряму для досвідчених користувачів.

```bash
# Print the database file path
bolt db path

# Open an interactive SQLite shell
bolt db

# Run an ad-hoc query
bolt db "SELECT id, title, time_updated FROM session ORDER BY time_updated DESC LIMIT 5"
```

Формат виводу за замовчуванням — значення, розділені табуляцією; додайте `--format json` для виводу JSON.

## Статистика використання токенів і вартості

`bolt stats` агрегує дані використання токенів і вартості за всіма вашими сесіями:

```bash
# All-time stats
bolt stats

# Last 7 days
bolt stats --days 7

# Current project only
bolt stats --project ""

# Show per-model breakdown (top 5 models)
bolt stats --models 5

# Limit tool-usage table to top 10 tools
bolt stats --tools 10
```

Вивід включає загальну кількість сесій, повідомлень, вхідних/вихідних токенів/токенів міркування/кешу, загальну вартість, середню вартість на день, середню й медіанну кількість токенів на сесію та розбивку використання інструментів. Передайте `--models`, щоб також показати розбивку повідомлень, токенів і вартості за моделями.

## Робочий процес форку та спільного доступу

Ось повний приклад форку сесії та обміну результатом:

<Steps>
  <Step title="Почніть роботу в новій сесії">
    ```bash
    bolt run "refactor the UserService to use dependency injection"
    ```
  </Step>
  <Step title="Розгалужте перед ризикованим наступним кроком">
    ```bash
    bolt run --continue --fork "also migrate it to the new Repository pattern"
    ```

    ID розгалуженої сесії виводиться в консоль. Оригінальна сесія залишається недоторканою.
  </Step>
  <Step title="Поділіться форком для ревʼю">
    ```bash
    bolt run --session <forked-id> --share "final cleanup and comments"
    ```

    URL спільного доступу виводиться, коли сесія переходить у стан бездіяльності.
  </Step>
  <Step title="Імпортуйте на іншому комп'ютері">
    ```bash
    bolt import https://opncd.ai/share/<slug>
    ```
  </Step>
</Steps>
