Більшість проблем Bolt належать до невеликої кількості категорій. Пройдіться відповідним акордеоном нижче й перевіряйте вивід логів за допомогою `bolt logs`, коли трапляється щось несподіване.

<Note>
  Для питань, на які тут немає відповіді, шукайте або починайте обговорення у [Bolt GitHub Discussions](https://github.com/bolt-builder/bolt-cli/discussions). Включайте вивід `bolt debug info` та `bolt logs --tail 50` у вашу публікацію, щоб спільнота могла допомогти швидше.
</Note>

## Перше, що варто спробувати

Перш ніж занурюватися в конкретний розділ, ці чотири команди розв'язують більшість проблем:

| Симптом | Перша команда | Чому |
| --- | --- | --- |
| Будь-що дивне | `bolt debug info` | Одноразовий підсумок системи \+ плагінів. |
| Щось працювало раніше, тепер ні | `bolt logs --tail 100` | Нещодавні помилки, зазвичай близько до верху. |
| Підозра на плагін | `bolt --pure` | Запуск із усіма вимкненими плагінами. |
| Конфігурація не підхоплюється | `bolt debug config` | Друкує повністю розв'язану конфігурацію. |

<Tip>
  Сімейство `bolt debug` — ваш перший пункт зупинки для будь-якої загадкової поведінки. `bolt debug info` для підсумку системи, `bolt debug config` для розв'язаної конфігурації, `bolt debug paths` для дискових розташувань, і `bolt debug snapshot`, щоб перевірити стан сесії.
</Tip>

<Accordion title="Bolt не запускається / падає під час запуску">
  **Симптоми:** Термінал блимає та одразу закривається, або ви бачите stack trace перед відображенням TUI.

  **Кроки:**

  <Steps>
    <Step title="Зберіть інформацію про систему">
      ```bash
      bolt debug info
      ```

      Це друкує вашу версію Bolt, ОС, емулятор термінала та завантажені плагіни. Копіюйте цей вивід, коли повідомляєте про помилку.
    </Step>
    <Step title="Перевірте нещодавній вивід логів">
      ```bash
      bolt logs --tail 100
      ```

      Шукайте рядки `ERROR`. Поширена причина — плагін, який не вдається завантажити — у такому випадку ви побачите помилку, що згадує ім'я плагіна.
    </Step>
    <Step title="Вимкніть плагіни, щоб ізолювати проблему">
      ```bash
      bolt --pure
      ```

      Якщо Bolt запускається чисто з `--pure`, плагін спричиняє збій. Видаліть проблемний плагін із конфігурації або повідомте авторові плагіна.
    </Step>
    <Step title="Перевірте, чи не пошкоджено конфігурацію">
      ```bash
      bolt debug config
      ```

      Якщо це друкує помилку про недійсний JSON, відкрийте файл конфігурації, який згадується, і виправте синтаксис. Запустіть `bolt db path`, щоб підтвердити, що шлях бази даних доступний.
    </Step>
  </Steps>
</Accordion>

<Accordion title="Автентифікація провайдера не вдається">
  **Симптоми:** Bolt показує "No providers configured", API-запити падають з помилками 401, або `bolt run` виходить одразу без будь-якого виводу.

  **Кроки:**

  <Steps>
    <Step title="Перезапустіть потік входу провайдера">
      ```bash
      bolt providers login
      ```

      Оберіть провайдера й дотримуйтеся підказок. Bolt проведе вас через введення API-ключа або OAuth.
    </Step>
    <Step title="Перевірте змінну середовища API-ключа">
      Якщо ви використовуєте env var (наприклад, `ANTHROPIC_API_KEY`), підтвердіть, що вона дійсно встановлена в поточній оболонці:

      ```bash
      echo $ANTHROPIC_API_KEY
      ```

      Якщо вона порожня, додайте її до профілю оболонки й перевідкрийте термінал.
    </Step>
    <Step title="Перегляньте розв'язану конфігурацію">
      ```bash
      bolt debug config
      ```

      Подивіться на розділ `provider`. Якщо ваш провайдер з'являється з порожнім `apiKey`, посилання на змінну середовища у вашому файлі конфігурації не розширюється.
    </Step>
    <Step title="Перегляньте збережені облікові дані">
      ```bash
      bolt providers list
      ```

      Це показує всі облікові дані, збережені в `auth.json`, і всі пов'язані з провайдерами змінні середовища, які виявив Bolt.
    </Step>
  </Steps>
</Accordion>

<Accordion title="MCP-сервер не підключається">
  **Симптоми:** `bolt mcp list` показує сервер як `failed` або `needs authentication`, або агент не може використовувати жодних інструментів з цього сервера.

  **Кроки:**

  <Steps>
    <Step title="Запустіть діагностичний зонд MCP">
      ```bash
      bolt mcp debug <server-name>
      ```

      Це тестує базове HTTP-підключення, перевіряє заголовок `WWW-Authenticate` та проходить через потік OAuth discovery, якщо застосовно. Вивід повідомить вам, чи сервер досяжний і чи потрібна автентифікація.
    </Step>
    <Step title="Перевірте URL сервера">
      Підтвердіть URL у вашому `.bolt/bolt.jsonc`. Для віддалених серверів переконайтеся, що URL закінчується шляхом MCP (наприклад, `/mcp` або `/tools`), а не лише хостом.
    </Step>
    <Step title="Повторно автентифікуйтеся для OAuth-серверів">
      ```bash
      bolt mcp auth <server-name>
      ```

      Дотримуйтеся потоку браузера. Якщо сервер вимагає попередньо зареєстрованого ID клієнта, додайте його до конфігурації:

      ```jsonc
      "mcp": {
        "my-server": {
          "type": "remote",
          "url": "https://mcp.example.com/tools",
          "oauth": {
            "clientId": "your-client-id",
            "clientSecret": "your-client-secret"
          }
        }
      }
      ```
    </Step>
    <Step title="Перевірте команду локального сервера">
      Для `local` серверів запустіть команду вручну в терміналі, щоб підтвердити, що вона стартує без помилок:

      ```bash
      npx @modelcontextprotocol/server-filesystem /tmp
      ```
    </Step>
  </Steps>
</Accordion>

<Accordion title="Сесію не знайдено">
  **Симптоми:** `bolt run --session <id>` виходить із "Session not found", або сесія, з якою ви пам'ятаєте, що працювали, зникла.

  **Кроки:**

  <Steps>
    <Step title="Перелічіть усі доступні сесії">
      ```bash
      bolt session list
      ```

      Сесії відсортовано за найпізнішим оновленням спочатку. Якщо вашу сесію видалено або базу даних мігровано, вона тут не з'явиться.
    </Step>
    <Step title="Знайдіть шлях бази даних">
      ```bash
      bolt db path
      ```

      Це друкує повний шлях до файлу SQLite. Підтвердіть, що файл існує й не порожній.
    </Step>
    <Step title="Запитайте базу даних безпосередньо">
      ```bash
      bolt db "SELECT id, title FROM sessions ORDER BY time_updated DESC LIMIT 20"
      ```

      Якщо ваша сесія з'являється у базі даних, але не в `bolt session list`, може бути невідповідність ID проєкту — сесії обмежені проєктами.
    </Step>
  </Steps>
</Accordion>

<Accordion title="Помилки дозволів у TUI">
  **Симптоми:** Агент неодноразово просить дозволу, відмовляється записувати файли, або ви бачите банери "Permission denied".

  **Розуміння рівнів доступу:**

  Кожен вбудований агент має задекларований рівень доступу, який контролює, що він може робити без запиту:

  | Рівень доступу | Що дозволяє |
  | --- | --- |
  | **Full** | Читати файли, писати файли, виконувати shell-команди |
  | **Edit** | Читати й писати файли, без shell-команд |
  | **Read** | Лише читати файли, без запису й команд |

  Агенти `code`, `debug`, `refactor`, `migrate` та `perf` мають доступ **Full**. `docs` має доступ **Edit**. `plan`, `ask`, `code-review` та `security` мають доступ **Read**.

  **Кроки:**

  <Steps>
    <Step title="Перемкніться на агента з доступом Full">
      Якщо вам потрібні записи файлів, використовуйте агента `code`:

      ```bash
      bolt run --agent code "implement the feature"
      ```

      Або натисніть `Tab` у TUI, щоб перебрати агентів.
    </Step>
    <Step title="Використайте --auto для неінтерактивного схвалення запитів">
      У CI або скриптових контекстах передайте `--auto` до `bolt run`, щоб автоматично схвалити дозволи, які не заборонено явно у конфігурації.
    </Step>
    <Step title="Налаштуйте дозволи у файлі конфігурації">
      Ви можете заборонити конкретні інструменти для всіх сесій у проєкті, додавши блок `permission` до `.bolt/bolt.jsonc`.
    </Step>
  </Steps>
</Accordion>

<Accordion title="Високе використання токенів або неочікувані витрати">
  **Симптоми:** `bolt stats` показує більшу кількість токенів, ніж очікувалося, або ваш API-рахунок росте швидше, ніж передбачалося.

  **Кроки:**

  <Steps>
    <Step title="Перегляньте статистику використання">
      ```bash
      bolt stats
      bolt stats --days 7 --models
      ```

      Вивід розкладає вартість на день, середню кількість токенів на сесію та використання за моделями.
    </Step>
    <Step title="Знизьте зусилля міркування">
      Для моделей, що підтримують це, зменшіть зусилля міркування за допомогою `--variant`:

      ```bash
      bolt run --model anthropic/claude-opus-4-5 --variant minimal "quick review"
      ```

      Підтримувані значення специфічні для провайдера (наприклад, `minimal`, `low`, `high`, `max`).
    </Step>
    <Step title="Перемкніться на дешевшу модель">
      Використовуйте `bolt models`, щоб знайти меншу модель. Менші моделі (наприклад, `claude-haiku`, `gpt-4o-mini`) коштують значно менше за токен і добре працюють для багатьох завдань.
    </Step>
    <Step title="Використовуйте агента ask або plan для дослідження">
      Агенти `ask` і `plan` мають доступ **Read** і не викликають інструментів запису, що означає, що вони уникають циклів з інтенсивним використанням інструментів, які генерують велику кількість вихідних токенів.
    </Step>
  </Steps>
</Accordion>

<Accordion title="Конфлікти плагінів або неочікувана поведінка">
  **Симптоми:** Slash-команда поводиться неочікувано, TUI відображається неправильно, або щось змінилося після встановлення плагіна.

  **Кроки:**

  <Steps>
    <Step title="Вимкніть усі плагіни, щоб встановити базовий рівень">
      ```bash
      bolt --pure
      ```

      Якщо проблема зникає, відповідальний плагін.
    </Step>
    <Step title="Ідентифікуйте проблемний плагін">
      ```bash
      bolt debug info
      ```

      Вивід перелічує всі завантажені плагіни. Тимчасово видаляйте їх по одному з конфігурації та перезапускайте Bolt, доки проблема не зникне.
    </Step>
    <Step title="Перевірте несумісність версій">
      ```bash
      bolt upgrade
      ```

      Плагіни оголошують сумісний діапазон версій Bolt. Якщо ви нещодавно оновили Bolt, плагін також може потребувати оновлення.
    </Step>
  </Steps>
</Accordion>

<Accordion title="Проблеми зі шляхами WSL / Windows">
  **Симптоми:** На Windows із WSL Bolt не може знайти `less`, шляхи файлів містять неочікувані зворотні слеші, або пейджер для `bolt session list` не запускається.

  **Кроки:**

  <Steps>
    <Step title="Встановіть шлях Git Bash">
      Bolt шукає Unix-утиліти (включно з `less`) відносно встановлення Git for Windows. Встановіть змінну середовища у ваш каталог Git Bash:

      ```powershell
      $env:BOLT_GIT_BASH_PATH = "C:\Program Files\Git\bin"
      ```

      Додайте це до профілю PowerShell (`$PROFILE`), щоб зберегти.
    </Step>
    <Step title="Перевірте за допомогою debug info">
      ```bash
      bolt debug info
      ```

      Підтверджує визначення ОС і які шляхи використовує Bolt.
    </Step>
    <Step title="Запускайте Bolt напряму всередині WSL">
      Для найкращого досвіду на Windows запускайте `bolt` із термінала WSL, а не з PowerShell чи Command Prompt.
    </Step>
  </Steps>
</Accordion>

<Accordion title="Не вдається оновити Bolt">
  **Симптоми:** `bolt upgrade` повідомляє про помилку або мовчки нічого не робить, або номер версії не змінюється після його запуску.

  **Кроки:**

  <Steps>
    <Step title="Явно вкажіть метод встановлення">
      Bolt намагається визначити, як його було встановлено. Якщо визначення не вдається, перевизначте:

      ```bash
      bolt upgrade --method npm
      bolt upgrade --method curl
      bolt upgrade --method brew
      ```
    </Step>
    <Step title="Перевстановіть через скрипт встановлення">
      ```bash
      curl -fsSL https://raw.githubusercontent.com/bolt-builder/bolt-cli/dev/install | bash
      ```
    </Step>
    <Step title="Windows: запуск від імені адміністратора для Chocolatey">
      Якщо ви встановили через `choco`, оновлення потребують піднятого термінала. Відкрийте PowerShell від імені адміністратора перед запуском `bolt upgrade`.
    </Step>
    <Step title="Підтвердіть, що активна нова версія">
      ```bash
      bolt --version
      which bolt    # verify the PATH is picking up the right binary
      ```
    </Step>
  </Steps>
</Accordion>

<Accordion title="Агент не може знайти файли (або знаходить забагато)">
  **Симптоми:** Агент скаржиться, що не бачить файлів, які існують, або постійно підбирає файли, до яких ви не хочете, щоб він торкався (як-от `node_modules`, вивід збірки або секрети).

  **Кроки:**

  <Steps>
    <Step title="Перевірте наявність .boltignore">
      Bolt дотримується файлу `.boltignore` у корені проєкту, який контролює, які файли можуть бачити інструменти пошуку файлів агента. Він використовує той самий синтаксис, що й `.gitignore`.

      ```text
      # .boltignore
      node_modules/
      .env*
      dist/
      *.pem
      ```
    </Step>
    <Step title="Підтвердіть робочий каталог">
      ```bash
      bolt debug info
      ```

      Перевірте, що `cwd` відповідає кореню проєкту. Якщо ви запустили Bolt із підкаталогу, пошук файлів агента вкорінено там.
    </Step>
    <Step title="Попросіть агента виконати grep, а не вгадувати">
      Якщо агент стверджує, що файл не існує, попросіть його явно запустити `grep` або `glob`. Це обходить будь-яке застаріле внутрішнє припущення.
    </Step>
  </Steps>
</Accordion>

<Accordion title="Отримання інформації для звіту про помилку">
  При поданні issue наступна інформація найкорисніша для мейнтейнерів:

  <Steps>
    <Step title="Зберіть інформацію про систему й плагіни">
      ```bash
      bolt debug info
      ```
    </Step>
    <Step title="Зберіть нещодавній вивід логів">
      ```bash
      bolt logs --tail 200
      ```
    </Step>
    <Step title="Експортуйте відповідну сесію (санітаризовану)">
      Якщо проблема сталася під час конкретної сесії, експортуйте її з прихованими секретами:

      ```bash
      bolt export --sanitize > session-debug.json
      ```

      Прикріпіть `session-debug.json` до issue.
    </Step>
    <Step title="Відкрийте issue або обговорення">
      Перейдіть до [GitHub Discussions](https://github.com/bolt-builder/bolt-cli/discussions) і вставте свій вивід `bolt debug info` плюс опис кроків для відтворення.
    </Step>
  </Steps>
</Accordion>
