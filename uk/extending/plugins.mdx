Плагіни дозволяють вам розширити Bolt за межі його вбудованих можливостей. Плагін — це модуль Node або Bun, що експортує маніфест плагіна Bolt; коли він завантажений, він може реєструвати нові LLM-провайдери, власні методи автентифікації, додаткові інструменти та адаптери робочого простору. Плагіни можна встановити для одного проєкту або застосувати глобально для всієї вашої роботи.

## Встановлення плагіна

Використовуйте `bolt plugin install` (псевдонім: `bolt plug`) для встановлення плагіна з npm і автоматичної реєстрації в конфігурації:

```bash
bolt plugin install <module>
```

### Прапорці

| Прапорець | Псевдонім | Опис |
|------|-------|-------------|
| `--global` | `-g` | Встановити в глобальну конфігурацію замість поточного проєкту |
| `--force` | `-f` | Замінити наявний запис для того самого модуля |

### Область: проєкт чи глобально

За замовчуванням `bolt plugin install` додає плагін до `.bolt/bolt.jsonc` на рівні проєкту. Передайте `--global`, щоб додати його до вашої користувацької конфігурації, і він завантажуватиметься в кожному проєкті.

```bash
# Project-scoped (default)
bolt plugin install @acme/bolt-plugin-jira

# Global — loads in every project
bolt plugin install @acme/bolt-plugin-jira --global
```

<Note>
  Запустіть `bolt --pure` (або встановіть `OPENCODE_PURE=1`), щоб запустити Bolt з усіма зовнішніми плагінами вимкненими. Це корисно для налагодження, коли плагін спричиняє неочікувану поведінку, без його видалення.
</Note>

## Встановлення опублікованого плагіна

<Steps>
  <Step title="Знайдіть пакет плагіна">
    Шукайте в npm пакети з `bolt-plugin` або `opencode-plugin` в імені або переходьте за посиланням з документації провайдера.
  </Step>

  <Step title="Встановіть у ваш проєкт">
    ```bash
    bolt plugin install @acme/bolt-plugin-jira
    ```

    Bolt встановлює пакет, читає його маніфест для виявлення цілей сервера та TUI, потім записує запис у `.bolt/bolt.jsonc`.
  </Step>

  <Step title="Перевірте конфігурацію">
    Відкрийте `.bolt/bolt.jsonc` і підтвердіть, що запис плагіна додано:

    ```jsonc
    {
      "plugin": [
        "@acme/bolt-plugin-jira"
      ]
    }
    ```
  </Step>

  <Step title="Запустіть сесію">
    ```bash
    bolt
    ```

    Bolt завантажує плагін під час запуску. Будь-які провайдери чи інструменти, які він реєструє, одразу доступні.
  </Step>
</Steps>

## Ручна конфігурація плагіна

Ви можете реєструвати плагіни, редагуючи `.bolt/bolt.jsonc` напряму. Це корисно для локальних плагінів на етапі розробки:

```jsonc
{
  "plugin": [
    "./plugins/my-plugin.ts"
  ]
}
```

Відносні шляхи розв'язуються від кореня проєкту. Підтримуються точки входу TypeScript і JavaScript.

## Створення плагіна

Плагіни розробляються з використанням пакета `@opencode-ai/plugin`, який надає інтерфейс `Hooks`, якому ваш модуль має відповідати.

```bash
npm install --save-dev @opencode-ai/plugin
```

Мінімальний плагін експортує функцію, що отримує об'єкт `PluginInput` і повертає об'єкт `Hooks`:

```typescript
import type { Plugin } from "@opencode-ai/plugin"

const myPlugin: Plugin = async (input) => {
  return {
    // auth hook — register custom authentication methods
    auth: {
      methods: [
        {
          id: "my-provider-auth",
          name: "My Provider",
          // ... provider-specific fields
        },
      ],
    },
  }
}

export default myPlugin
```

### Доступні типи хуків

| Хук | Призначення |
|------|---------|
| `auth` | Реєструє власних провайдерів автентифікації з масивом `methods` |
| `event` | Реагує на події сесії (повідомлення, виклики інструментів, завершення) |
| `config` | Реагує на зміни конфігурації під час виконання |
| `dispose` | Прибирає ресурси при вивантаженні плагіна |

Об'єкт `PluginInput` надає `client` (типізований API-клієнт Bolt), `project`, `worktree`, `directory` та `serverUrl`, щоб ваш плагін міг взаємодіяти із запущеним сервером.
