Model Context Protocol (MCP) — це відкритий стандарт, який дозволяє AI-агентам спілкуватися із зовнішніми інструментами та джерелами даних через спільний інтерфейс. Bolt використовує MCP для розширення можливостей агентів — під'єднаний MCP-сервер може виставляти будь-що, від інструменту запиту до бази даних до повного API веб-пошуку. Bolt керує повним життєвим циклом: додаванням серверів, запуском OAuth-потоків, оновленням токенів і перевіркою підключення.

## Типи серверів

Bolt підтримує два види MCP-серверів.

| Тип | Транспорт | Опис |
|------|-----------|-------------|
| `remote` | HTTP / SSE (Streamable HTTP) | Сервер, що працює за URL, доступним по мережі |
| `local` | stdio | Локальна команда, яку Bolt породжує як дочірній процес |

Віддалені сервери підтримують OAuth-автентифікацію одразу. Bolt виконує отримання токенів, зберігання та автоматичне оновлення — вам ніколи не потрібно керувати токенами вручну.

## Команди

### `bolt mcp add`

Додає новий MCP-сервер інтерактивно або одним викликом.

**Інтерактивно** — запустіть `bolt mcp add` без аргументів, щоб пройти майстер із запитами, що просить ім'я, область (проєкт або глобально), тип, URL чи команду, та чи використовує сервер OAuth.

**Неінтерактивно** — надайте ім'я плюс `--url` для віддаленого сервера або команду після `--` для локального:

<CodeGroup>

```bash Remote server
bolt mcp add my-server --url https://my-mcp-server.example.com/mcp
```

```bash Remote server with OAuth credentials
bolt mcp add my-server --url https://my-mcp-server.example.com/mcp
# OAuth prompts appear in the interactive flow
```

```bash Local stdio server
bolt mcp add filesystem -- npx -y @modelcontextprotocol/server-filesystem /tmp
```

```bash Remote server with custom HTTP headers
bolt mcp add my-server --url https://my-mcp-server.example.com/mcp \
  --header "Authorization=Bearer sk-abc123"
```

</CodeGroup>

**Прапорці для `bolt mcp add`**

| Прапорець | Опис |
|------|-------------|
| `--url <url>` | URL віддаленого MCP-сервера |
| `--header <KEY=VALUE>` | HTTP-заголовок для надсилання віддаленому серверу (повторюваний) |
| `--env <KEY=VALUE>` | Змінна середовища для локального сервера (повторювана) |

### `bolt mcp list`

Перелічує кожен налаштований MCP-сервер разом із його статусом підключення та автентифікації.

```bash
bolt mcp list
```

Кожен запис показує іконку статусу:

| Іконка | Значення |
|------|---------|
| `✓` | Під'єднано (та автентифіковано, якщо використовується OAuth) |
| `⚠` | Потребує автентифікації або облікові дані застаріли |
| `✗` | Не вдалося під'єднатися або потрібна реєстрація клієнта |
| `○` | Ще не ініціалізовано або вимкнено |

### `bolt mcp auth <name>`

Автентифікація з віддаленим MCP-сервером з увімкненим OAuth. Якщо ви пропустите ім'я, Bolt покаже інтерактивний селектор, що перелічує всі сервери, здатні до OAuth, разом із їх поточним статусом автентифікації (`✓ authenticated`, `⚠ expired`, `✗ not authenticated`).

```bash
# Authenticate a specific server
bolt mcp auth my-server

# Pick from a list of OAuth-capable servers
bolt mcp auth
```

Bolt відкриває ваш браузер за URL авторизації провайдера та чекає на зворотний виклик — повний OAuth-обмін, включно з динамічною реєстрацією клієнта за потреби, відбувається автоматично.

<Note>
  Bolt виконує повний OAuth-потік, включно зі збереженням токенів та автоматичним оновленням токенів. Вам не потрібно копіювати токени чи керувати терміном придатності вручну. Якщо сервер вимагає попередньо зареєстрованого ID клієнта, додайте `oauth.clientId` (і, за потреби, `oauth.clientSecret`) до запису конфігурації сервера в `.bolt/bolt.jsonc`.
</Note>

---

### `bolt mcp logout <name>`

Видаляє збережені OAuth-облікові дані для сервера. Якщо ви пропустите ім'я, Bolt попросить вас обрати зі списку серверів, що мають збережені токени.

```bash
bolt mcp logout my-server
```

---

### `bolt mcp debug <name>`

Перевіряє підключення віддаленого сервера й переглядає його стан OAuth без запуску повної сесії. Це перший інструмент, до якого варто звернутися, коли сервер показує `✗ failed` або `⚠ needs authentication`.

```bash
bolt mcp debug my-server
```

`debug` повідомляє:
- URL сервера та поточний статус автентифікації
- Деталі access-токена (замасковано) та часову мітку терміну придатності
- Наявність refresh-токена
- Сирий HTTP-код відповіді від сервера
- Вміст заголовка `WWW-Authenticate`
- Результат зондування OAuth discovery (без завершення потоку)

## Ручна конфігурація

Ви можете додавати чи редагувати MCP-сервери безпосередньо в `.bolt/bolt.jsonc` без використання команд CLI. Bolt підхоплює зміни під час наступного запуску сесії.

```jsonc
{
  "mcp": {
    "my-server": {
      "type": "remote",
      "url": "https://my-mcp-server.example.com/mcp"
    }
  }
}
```

Локальний stdio-сервер виглядає так:

```jsonc
{
  "mcp": {
    "filesystem": {
      "type": "local",
      "command": ["npx", "-y", "@modelcontextprotocol/server-filesystem", "/tmp"]
    }
  }
}
```

Щоб надати власні HTTP-заголовки чи вимкнути OAuth на віддаленому сервері:

```jsonc
{
  "mcp": {
    "my-server": {
      "type": "remote",
      "url": "https://my-mcp-server.example.com/mcp",
      "headers": {
        "Authorization": "Bearer sk-abc123"
      },
      "oauth": false
    }
  }
}
```

## Додавання й автентифікація віддаленого MCP-сервера

<Steps>
  <Step title="Додайте сервер">
    Запустіть `bolt mcp add` і дотримуйтеся запитів, або використайте неінтерактивну форму:

    ```bash
    bolt mcp add my-server --url https://my-mcp-server.example.com/mcp
    ```

    Bolt записує запис у `.bolt/bolt.jsonc` (область проєкту) або в глобальну конфігурацію.
  </Step>

  <Step title="Перевірте статус підключення">
    ```bash
    bolt mcp list
    ```

    Якщо сервер вимагає автентифікації, ви побачите `⚠ needs authentication` поруч із його ім'ям.
  </Step>

  <Step title="Автентифікуйтеся за допомогою OAuth">
    ```bash
    bolt mcp auth my-server
    ```

    Bolt відкриває ваш браузер. Після того як ви схвалите доступ, термінал підтвердить успішну автентифікацію, а статус сервера зміниться на `✓ connected (OAuth)`.
  </Step>

  <Step title="Перевірте, що інструменти доступні">
    Запустіть сесію Bolt. Інструменти, виставлені сервером, тепер доступні всім агентам. Ви можете перевірити їх у будь-який час:

    ```bash
    bolt mcp debug my-server
    ```
  </Step>
</Steps>
