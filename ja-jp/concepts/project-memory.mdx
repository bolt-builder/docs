プロジェクトメモリは、Bolt がプロジェクトをすでに知っているように感じさせるものです。セッションがそのターンを終えると、Bolt は役立つ情報を抽出し、プロジェクトごとのメモリストアに書き込みます。新しいセッションを開くと、Bolt はメモリインデックスと最新のセッションダイジェストをシステムプロンプトに注入するので、エージェントは白紙の状態ではなく実際のコンテキストから始まります。

## キャプチャの仕組み

各会話ターンの終了時に、Bolt はモデルに、次回役立つ永続的な事実を要約するよう求めます。慣習、アーキテクチャに関するメモ、ファイル配置、ビルド/テストコマンド、注意点、未解決のスレッドなどです。これらはプロジェクトのメモリディレクトリの下のディスクに、最新セッションのローリングダイジェストと共に書き込まれます。

メモリはプロジェクトごとです。同じマシン上の同じリポジトリの 2 つのチェックアウトはメモリを共有します。無関係なプロジェクトが互いのメモリを見ることはありません。

## 明示的なツール

エージェントはセッション中にメモリを直接読み書きすることもできます。

- `memory_save` — エージェントが次回覚えておくべき特定の事実を記録します。
- `memory_recall` — エージェント (またはあなた) が以前にキャプチャした情報を検索します。

「pnpm を使う、npm ではない、と覚えておいて」とエージェントに頼めば、`memory_save` を呼び出してくれます。

## セッションごとの制御

TUI 内では、スラッシュコマンドで現在のセッションのメモリ動作を切り替えられます。

```text
/memory use on|off         # このセッションがプロジェクトメモリを読むかどうか
/memory contribute on|off  # このセッションがメモリに書き戻すかどうか
```

これは、メモリを汚さない使い捨ての探索的セッションが必要な場合や、以前のコンテキストの恩恵は受けつつも読み取り専用のセッションが必要な場合に便利です。

## メモリの検査と編集

```bash
bolt memory           # inspect the memory store for the current project
```

メモリはプロジェクトの Bolt データディレクトリの下にプレーンなファイルとしてディスクに保存されるので、エントリを直接 grep、編集、削除できます。マシン上の正確なパスを見つけるには `bolt debug paths` を実行してください。
