カスタムツールを使うと、スクリプト化できるあらゆるもの (シェルスクリプト、Node/Bun/Python プログラム、小さなバイナリ) を、エージェントが名前で呼び出せるツールとして公開できます。プロジェクト独自のビルド、デプロイ、データワークフローへのアクセスを Bolt に与える最もシンプルな方法です。

## 配置場所

次のいずれかにファイルをドロップします。

- `.opencode/tool/` — プロジェクトスコープ、リポジトリと共にチェックインされます。
- `.opencode/tools/` — 上記のエイリアスとして受け入れられます。

各ファイルは、ファイル名 (拡張子を除く) をツール名として持つツールになります。ツールは次に Bolt が起動する際に自動的にピックアップされます。

## ツールの構造

カスタムツールはヘッダーで名前、説明、入力スキーマを宣言し、動作を実装します。正確な形は選ぶランタイム (シェルスクリプト、TypeScript など) によりますが、すべてのツールは次を行う必要があります。

1. 入力用の JSON Schema を宣伝して、モデルがどう呼び出すかを知れるようにします。
2. Bolt が TUI にレンダリングしてモデルにフィードバックできる値 (またはエラー) を返します。

一度ロードされると、ツールは `bash` や `grep` などの組み込みツールの隣にエージェントのツールリストに表示され、同じ [権限](/concepts/permissions) システムでゲートされます。

## カスタムツール vs. MCP サーバ をいつ使うか

- **カスタムツール** — 小さい、プロジェクト固有、プロジェクト間で再利用しない。書くのが速いです。
- **MCP サーバ** — プロジェクト間で共有される、または認証を伴う実際の外部サービスをラップします。[MCP サーバ](/extending/mcp-servers) を参照してください。
- **プラグインツール** — 他の拡張ポイントと共に npm パッケージとして配布します。[プラグイン](/extending/plugins) を参照してください。
