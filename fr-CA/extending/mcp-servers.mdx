Le Model Context Protocol (MCP) est un standard ouvert qui permet aux agents IA de communiquer avec des outils et sources de données externes via une interface commune. Bolt utilise MCP pour étendre les capacités des agents — un serveur MCP connecté peut exposer n'importe quoi, d'un outil d'interrogation de base de données à une API complète de recherche Web. Bolt gère l'ensemble du cycle de vie : ajout de serveurs, exécution de flux OAuth, rafraîchissement de jetons et sondage de connectivité.

## Types de serveurs

Bolt prend en charge deux types de serveurs MCP.

| Type | Transport | Description |
|------|-----------|-------------|
| `remote` | HTTP / SSE (Streamable HTTP) | Un serveur fonctionnant à une URL accessible sur le réseau |
| `local` | stdio | Une commande locale que Bolt lance comme processus enfant |

Les serveurs distants prennent en charge l'authentification OAuth d'emblée. Bolt gère l'acquisition, le stockage et le rafraîchissement automatique des jetons — vous ne gérez jamais les jetons à la main.

## Commandes

### `bolt mcp add`

Ajouter un nouveau serveur MCP de façon interactive ou en une seule fois.

**Interactif** — exécutez `bolt mcp add` sans arguments pour parcourir un assistant piloté par invite qui demande le nom, la portée (projet ou global), le type, l'URL ou la commande, et si le serveur utilise OAuth.

**Non-interactif** — fournissez un nom plus soit `--url` pour un serveur distant, soit une commande après `--` pour un serveur local :

<CodeGroup>

```bash Remote server
bolt mcp add my-server --url https://my-mcp-server.example.com/mcp
```

```bash Remote server with OAuth credentials
bolt mcp add my-server --url https://my-mcp-server.example.com/mcp
# OAuth prompts appear in the interactive flow
```

```bash Local stdio server
bolt mcp add filesystem -- npx -y @modelcontextprotocol/server-filesystem /tmp
```

```bash Remote server with custom HTTP headers
bolt mcp add my-server --url https://my-mcp-server.example.com/mcp \
  --header "Authorization=Bearer sk-abc123"
```

</CodeGroup>

**Indicateurs pour `bolt mcp add`**

| Indicateur | Description |
|------|-------------|
| `--url <url>` | URL d'un serveur MCP distant |
| `--header <KEY=VALUE>` | En-tête HTTP à envoyer à un serveur distant (répétable) |
| `--env <KEY=VALUE>` | Variable d'environnement pour un serveur local (répétable) |

---

### `bolt mcp list`

Liste tous les serveurs MCP configurés ainsi que leur état de connexion et d'authentification.

```bash
bolt mcp list
```

Chaque entrée affiche une icône d'état :

| Icône | Signification |
|------|---------|
| `✓` | Connecté (et authentifié si OAuth est utilisé) |
| `⚠` | Nécessite une authentification ou les identifiants sont expirés |
| `✗` | Échec de connexion ou enregistrement de client requis |
| `○` | Pas encore initialisé ou désactivé |

---

### `bolt mcp auth <name>`

Authentifiez-vous avec un serveur MCP distant compatible OAuth. Si vous omettez le nom, Bolt affiche un sélecteur interactif listant tous les serveurs capables d'OAuth avec leur état d'authentification actuel (`✓ authenticated`, `⚠ expired`, `✗ not authenticated`).

```bash
# Authenticate a specific server
bolt mcp auth my-server

# Pick from a list of OAuth-capable servers
bolt mcp auth
```

Bolt ouvre votre navigateur à l'URL d'autorisation du fournisseur et attend le rappel — la poignée de main OAuth complète, y compris l'enregistrement dynamique du client au besoin, se déroule automatiquement.

<Note>
  Bolt gère le flux OAuth complet, y compris le stockage et le rafraîchissement automatique des jetons. Vous n'avez pas à copier des jetons ou à gérer l'expiration manuellement. Si un serveur requiert un ID client préenregistré, ajoutez `oauth.clientId` (et optionnellement `oauth.clientSecret`) à l'entrée de configuration du serveur dans `.bolt/bolt.jsonc`.
</Note>

---

### `bolt mcp logout <name>`

Retire les identifiants OAuth stockés pour un serveur. Si vous omettez le nom, Bolt vous invite à choisir dans une liste de serveurs ayant des jetons stockés.

```bash
bolt mcp logout my-server
```

---

### `bolt mcp debug <name>`

Sonde la connectivité d'un serveur distant et inspecte son état OAuth sans démarrer une session complète. C'est le premier outil à utiliser quand un serveur affiche `✗ failed` ou `⚠ needs authentication`.

```bash
bolt mcp debug my-server
```

`debug` rapporte :
- L'URL du serveur et l'état d'authentification actuel
- Les détails du jeton d'accès (masqués) et l'horodatage d'expiration
- La présence ou non d'un jeton de rafraîchissement
- Le code de réponse HTTP brut du serveur
- Le contenu de l'en-tête `WWW-Authenticate`
- Le résultat d'une sonde de découverte OAuth (sans compléter le flux)

## Configuration manuelle

Vous pouvez ajouter ou modifier des serveurs MCP directement dans `.bolt/bolt.jsonc` sans utiliser les commandes CLI. Bolt prend en compte les changements au démarrage de la session suivante.

```jsonc
{
  "mcp": {
    "my-server": {
      "type": "remote",
      "url": "https://my-mcp-server.example.com/mcp"
    }
  }
}
```

Un serveur stdio local ressemble à ceci :

```jsonc
{
  "mcp": {
    "filesystem": {
      "type": "local",
      "command": ["npx", "-y", "@modelcontextprotocol/server-filesystem", "/tmp"]
    }
  }
}
```

Pour fournir des en-têtes HTTP personnalisés ou désactiver OAuth sur un serveur distant :

```jsonc
{
  "mcp": {
    "my-server": {
      "type": "remote",
      "url": "https://my-mcp-server.example.com/mcp",
      "headers": {
        "Authorization": "Bearer sk-abc123"
      },
      "oauth": false
    }
  }
}
```

## Ajouter et authentifier un serveur MCP distant

<Steps>
  <Step title="Ajouter le serveur">
    Exécutez `bolt mcp add` et suivez les invites, ou utilisez la forme non interactive :

    ```bash
    bolt mcp add my-server --url https://my-mcp-server.example.com/mcp
    ```

    Bolt écrit l'entrée dans `.bolt/bolt.jsonc` (portée du projet) ou dans votre configuration globale.
  </Step>

  <Step title="Vérifier l'état de la connexion">
    ```bash
    bolt mcp list
    ```

    Si le serveur requiert une authentification, vous verrez `⚠ needs authentication` à côté de son nom.
  </Step>

  <Step title="S'authentifier avec OAuth">
    ```bash
    bolt mcp auth my-server
    ```

    Bolt ouvre votre navigateur. Après que vous ayez approuvé l'accès, le terminal confirme que l'authentification a réussi et l'état du serveur passe à `✓ connected (OAuth)`.
  </Step>

  <Step title="Vérifier que les outils sont disponibles">
    Démarrez une session Bolt. Les outils exposés par le serveur sont maintenant disponibles pour tous les agents. Vous pouvez les inspecter à tout moment :

    ```bash
    bolt mcp debug my-server
    ```
  </Step>
</Steps>
