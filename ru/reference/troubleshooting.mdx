Большинство проблем Bolt попадает в небольшое число категорий. Пройдитесь по подходящему разделу ниже и проверяйте вывод логов через `bolt logs`, если случается что-то неожиданное.

<Note>
  Если ответа на ваш вопрос здесь нет, ищите или начните обсуждение в [GitHub Discussions Bolt](https://github.com/bolt-builder/bolt-cli/discussions). Приложите вывод `bolt debug info` и `bolt logs --tail 50`, чтобы сообщество помогло быстрее.
</Note>

## Что попробовать в первую очередь

Прежде чем нырять в конкретный раздел, эти четыре команды решают большинство проблем:

| Симптом | Первая команда | Почему |
| --- | --- | --- |
| Что-то странное | `bolt debug info` | Одна команда — сводка по системе \+ плагинам. |
| Раньше работало, теперь нет | `bolt logs --tail 100` | Свежие ошибки, обычно ближе к началу. |
| Подозреваете плагин | `bolt --pure` | Запуск с полностью отключёнными плагинами. |
| Конфигурация не подхватывается | `bolt debug config` | Печатает полностью разрешённую конфигурацию. |

<Tip>
  Семейство `bolt debug` — первая остановка при любом непонятном поведении. `bolt debug info` для сводки системы, `bolt debug config` для разрешённой конфигурации, `bolt debug paths` для путей на диске и `bolt debug snapshot` для инспекта состояния сессии.
</Tip>

<Accordion title="Bolt не стартует / падает при запуске">
  **Симптомы:** Терминал вспыхивает и сразу выходит, либо вы видите стектрейс до отрисовки TUI.

  **Шаги:**

  <Steps>
    <Step title="Соберите информацию о системе">
      ```bash
      bolt debug info
      ```

      Выводит вашу версию Bolt, ОС, эмулятор терминала и загруженные плагины. Скопируйте этот вывод при отправке багрепорта.
    </Step>
    <Step title="Проверьте свежие логи">
      ```bash
      bolt logs --tail 100
      ```

      Ищите строки `ERROR`. Частая причина — плагин, который не загружается; в этом случае вы увидите ошибку с упоминанием имени плагина.
    </Step>
    <Step title="Отключите плагины, чтобы изолировать проблему">
      ```bash
      bolt --pure
      ```

      Если Bolt чисто запускается с `--pure`, крэш вызывает плагин. Удалите проблемный плагин из конфигурации или сообщите его автору.
    </Step>
    <Step title="Проверьте на повреждённую конфигурацию">
      ```bash
      bolt debug config
      ```

      Если это выводит ошибку о неверном JSON, откройте упомянутый файл конфигурации и исправьте синтаксис. Запустите `bolt db path`, чтобы убедиться, что путь к базе доступен.
    </Step>
  </Steps>
</Accordion>

<Accordion title="Не удаётся аутентификация провайдера">
  **Симптомы:** Bolt показывает "No providers configured", запросы к API падают с 401, или `bolt run` немедленно завершается без вывода.

  **Шаги:**

  <Steps>
    <Step title="Перезапустите поток логина провайдера">
      ```bash
      bolt providers login
      ```

      Выберите провайдера и следуйте подсказкам. Bolt проведёт вас через ввод API-ключа или OAuth.
    </Step>
    <Step title="Проверьте переменную окружения с API-ключом">
      Если вы используете env-переменную (например, `ANTHROPIC_API_KEY`), убедитесь, что она действительно установлена в текущем shell:

      ```bash
      echo $ANTHROPIC_API_KEY
      ```

      Если пусто, добавьте её в профиль shell и заново откройте терминал.
    </Step>
    <Step title="Проверьте разрешённую конфигурацию">
      ```bash
      bolt debug config
      ```

      Посмотрите на секцию `provider`. Если ваш провайдер отображается с пустым `apiKey`, ссылка на переменную окружения в файле конфигурации не раскрывается.
    </Step>
    <Step title="Посмотрите сохранённые учётные данные">
      ```bash
      bolt providers list
      ```

      Это показывает все учётные данные, сохранённые в `auth.json`, и все обнаруженные Bolt переменные окружения, связанные с провайдерами.
    </Step>
  </Steps>
</Accordion>

<Accordion title="MCP-сервер не подключается">
  **Симптомы:** `bolt mcp list` показывает сервер как `failed` или `needs authentication`, либо агент не может использовать инструменты с этого сервера.

  **Шаги:**

  <Steps>
    <Step title="Запустите MCP debug-проверку">
      ```bash
      bolt mcp debug <server-name>
      ```

      Это проверяет базовую HTTP-связность, инспектирует заголовок `WWW-Authenticate` и проходит по потоку OAuth discovery, если применимо. Вывод скажет вам, доступен ли сервер и требуется ли аутентификация.
    </Step>
    <Step title="Проверьте URL сервера">
      Проверьте URL в `.bolt/bolt.jsonc`. Для удалённых серверов убедитесь, что URL заканчивается на MCP-путь (например, `/mcp` или `/tools`), а не только на хост.
    </Step>
    <Step title="Переаутентифицируйтесь для OAuth-серверов">
      ```bash
      bolt mcp auth <server-name>
      ```

      Пройдите по потоку в браузере. Если сервер требует предзарегистрированный client ID, добавьте его в конфигурацию:

      ```jsonc
      "mcp": {
        "my-server": {
          "type": "remote",
          "url": "https://mcp.example.com/tools",
          "oauth": {
            "clientId": "your-client-id",
            "clientSecret": "your-client-secret"
          }
        }
      }
      ```
    </Step>
    <Step title="Проверьте локальную команду сервера">
      Для `local` серверов запустите команду вручную в терминале, чтобы убедиться, что она стартует без ошибок:

      ```bash
      npx @modelcontextprotocol/server-filesystem /tmp
      ```
    </Step>
  </Steps>
</Accordion>

<Accordion title="Сессия не найдена">
  **Симптомы:** `bolt run --session <id>` завершается с "Session not found", или сессия, с которой вы, помните, работали, исчезла.

  **Шаги:**

  <Steps>
    <Step title="Список всех доступных сессий">
      ```bash
      bolt session list
      ```

      Сессии отсортированы по самой недавно обновлённой. Если ваша сессия удалена или база была мигрирована, она здесь не появится.
    </Step>
    <Step title="Найдите путь к базе">
      ```bash
      bolt db path
      ```

      Это выводит полный путь к файлу SQLite. Убедитесь, что файл существует и не пуст.
    </Step>
    <Step title="Запросите базу напрямую">
      ```bash
      bolt db "SELECT id, title FROM sessions ORDER BY time_updated DESC LIMIT 20"
      ```

      Если ваша сессия есть в базе, но не в `bolt session list`, возможно, есть несоответствие ID проекта — сессии привязаны к проектам.
    </Step>
  </Steps>
</Accordion>

<Accordion title="Ошибки разрешений в TUI">
  **Симптомы:** Агент постоянно запрашивает разрешение, отказывается писать в файлы, либо вы видите баннеры «Permission denied».

  **Понимание уровней доступа:**

  У каждого встроенного агента есть заявленный уровень доступа, который определяет, что он может делать без запроса:

  | Уровень доступа | Что разрешает |
  | --- | --- |
  | **Full** | Чтение файлов, запись файлов, выполнение shell-команд |
  | **Edit** | Чтение и запись файлов, без shell-команд |
  | **Read** | Только чтение файлов, без записи и команд |

  Агенты `code`, `debug`, `refactor`, `migrate` и `perf` имеют доступ **Full**. `docs` имеет **Edit**. `plan`, `ask`, `code-review` и `security` имеют **Read**.

  **Шаги:**

  <Steps>
    <Step title="Переключитесь на агента с доступом Full">
      Если нужны записи в файлы, используйте агента `code`:

      ```bash
      bolt run --agent code "implement the feature"
      ```

      Или нажмите `Tab` в TUI, чтобы перебрать агентов.
    </Step>
    <Step title="Используйте --auto для неинтерактивного одобрения запросов">
      В CI или скриптах передавайте `--auto` в `bolt run`, чтобы автоодобрять разрешения, которые не запрещены явно в конфигурации.
    </Step>
    <Step title="Настройте разрешения в файле конфигурации">
      Можно запретить конкретные инструменты для всех сессий проекта, добавив блок `permission` в `.bolt/bolt.jsonc`.
    </Step>
  </Steps>
</Accordion>

<Accordion title="Высокое использование токенов или неожиданные расходы">
  **Симптомы:** `bolt stats` показывает большее число токенов, чем ожидалось, либо ваш счёт по API растёт быстрее, чем предполагалось.

  **Шаги:**

  <Steps>
    <Step title="Просмотрите статистику использования">
      ```bash
      bolt stats
      bolt stats --days 7 --models
      ```

      Вывод разбивает стоимость по дням, средние токены на сессию и использование по моделям.
    </Step>
    <Step title="Снизьте усилие рассуждения">
      Для моделей, которые это поддерживают, снизьте усилие рассуждения через `--variant`:

      ```bash
      bolt run --model anthropic/claude-opus-4-5 --variant minimal "quick review"
      ```

      Поддерживаемые значения зависят от провайдера (например, `minimal`, `low`, `high`, `max`).
    </Step>
    <Step title="Переключитесь на более дешёвую модель">
      Используйте `bolt models`, чтобы найти меньшую модель. Меньшие модели (например, `claude-haiku`, `gpt-4o-mini`) стоят значительно меньше за токен и хорошо работают для многих задач.
    </Step>
    <Step title="Используйте агентов ask или plan для исследования">
      Агенты `ask` и `plan` имеют доступ **Read** и не вызывают инструменты записи, что позволяет избегать циклов с большими выходными токенами.
    </Step>
  </Steps>
</Accordion>

<Accordion title="Конфликты плагинов или неожиданное поведение">
  **Симптомы:** Слэш-команда ведёт себя неожиданно, TUI отрисовывается неправильно, или что-то изменилось после установки плагина.

  **Шаги:**

  <Steps>
    <Step title="Отключите все плагины, чтобы задать базовую линию">
      ```bash
      bolt --pure
      ```

      Если проблема исчезает, виноват плагин.
    </Step>
    <Step title="Определите проблемный плагин">
      ```bash
      bolt debug info
      ```

      Вывод перечисляет все загруженные плагины. Временно удаляйте их из конфигурации по одному и перезапускайте Bolt, пока проблема не исчезнет.
    </Step>
    <Step title="Проверьте несовместимость версий">
      ```bash
      bolt upgrade
      ```

      Плагины объявляют совместимый диапазон версий Bolt. Если вы недавно обновили Bolt, плагин может также нуждаться в обновлении.
    </Step>
  </Steps>
</Accordion>

<Accordion title="Проблемы с путями в WSL / Windows">
  **Симптомы:** На Windows с WSL Bolt не находит `less`, пути к файлам содержат неожиданные обратные слэши, либо не запускается пейджер для `bolt session list`.

  **Шаги:**

  <Steps>
    <Step title="Задайте путь к Git Bash">
      Bolt ищет Unix-утилиты (в том числе `less`) относительно установки Git for Windows. Установите переменную окружения на каталог Git Bash:

      ```powershell
      $env:BOLT_GIT_BASH_PATH = "C:\Program Files\Git\bin"
      ```

      Добавьте это в свой профиль PowerShell (`$PROFILE`), чтобы сохранить.
    </Step>
    <Step title="Проверьте через debug info">
      ```bash
      bolt debug info
      ```

      Подтверждает определение ОС и какие пути использует Bolt.
    </Step>
    <Step title="Запускайте Bolt прямо внутри WSL">
      Для лучшего опыта на Windows запускайте `bolt` из терминала WSL, а не из PowerShell или командной строки.
    </Step>
  </Steps>
</Accordion>

<Accordion title="Не удаётся обновить Bolt">
  **Симптомы:** `bolt upgrade` сообщает об ошибке или ничего не делает, либо номер версии не меняется после запуска.

  **Шаги:**

  <Steps>
    <Step title="Явно укажите метод установки">
      Bolt пытается определить, как он был установлен. Если определение не удаётся, переопределите его:

      ```bash
      bolt upgrade --method npm
      bolt upgrade --method curl
      bolt upgrade --method brew
      ```
    </Step>
    <Step title="Переустановите через скрипт установки">
      ```bash
      curl -fsSL https://raw.githubusercontent.com/bolt-builder/bolt-cli/dev/install | bash
      ```
    </Step>
    <Step title="Windows: запуск как администратор для Chocolatey">
      Если вы устанавливали через `choco`, обновления требуют повышенного терминала. Откройте PowerShell как администратор перед запуском `bolt upgrade`.
    </Step>
    <Step title="Убедитесь, что новая версия активна">
      ```bash
      bolt --version
      which bolt    # проверьте, что PATH подхватывает нужный бинарник
      ```
    </Step>
  </Steps>
</Accordion>

<Accordion title="Агент не находит файлы (или находит слишком много)">
  **Симптомы:** Агент жалуется, что не видит существующие файлы, либо постоянно подхватывает файлы, которые вы не хотите ему трогать (вроде `node_modules`, вывод сборки или секреты).

  **Шаги:**

  <Steps>
    <Step title="Проверьте наличие .boltignore">
      Bolt соблюдает файл `.boltignore` в корне проекта, который контролирует, какие файлы видят инструменты поиска агента. Использует тот же синтаксис, что и `.gitignore`.

      ```text
      # .boltignore
      node_modules/
      .env*
      dist/
      *.pem
      ```
    </Step>
    <Step title="Подтвердите рабочий каталог">
      ```bash
      bolt debug info
      ```

      Проверьте, что `cwd` совпадает с корнем проекта. Если вы запустили Bolt из подкаталога, поиск файлов агента будет корнем оттуда.
    </Step>
    <Step title="Попросите агента искать через grep, а не гадать">
      Если агент утверждает, что файла не существует, попросите его явно запустить `grep` или `glob`. Это обходит любые устаревшие внутренние допущения.
    </Step>
  </Steps>
</Accordion>

<Accordion title="Сбор debug-информации для багрепорта">
  При подаче issue наиболее полезны для мейнтейнеров следующие сведения:

  <Steps>
    <Step title="Соберите информацию о системе и плагинах">
      ```bash
      bolt debug info
      ```
    </Step>
    <Step title="Соберите свежие логи">
      ```bash
      bolt logs --tail 200
      ```
    </Step>
    <Step title="Экспортируйте нужную сессию (очищенную)">
      Если проблема случилась в конкретной сессии, экспортируйте её с редактированием секретов:

      ```bash
      bolt export --sanitize > session-debug.json
      ```

      Прикрепите `session-debug.json` к issue.
    </Step>
    <Step title="Откройте issue или обсуждение">
      Перейдите в [GitHub Discussions](https://github.com/bolt-builder/bolt-cli/discussions) и вставьте вывод `bolt debug info` вместе с описанием шагов для воспроизведения.
    </Step>
  </Steps>
</Accordion>
