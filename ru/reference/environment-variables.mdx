Переменные окружения позволяют настраивать Bolt без правки файлов конфигурации — удобно в CI-пайплайнах, Docker-контейнерах и совместных окружениях, где нельзя коммитить учётные данные. Они читаются один раз при запуске и не могут быть изменены во время работы Bolt.

## Справочник

| Переменная | Описание |
| --- | --- |
| `BOLT_LOG_LEVEL` | Установить уровень логирования. Принимаемые значения: `DEBUG`, `INFO`, `WARN`, `ERROR`. Эквивалент флага `--log-level`. |
| `BOLT_PRINT_LOGS` | Установите в любое непустое значение, чтобы печатать вывод логов в stderr. Эквивалент `--print-logs`. |
| `BOLT_PURE` | Установите в любое непустое значение, чтобы отключить все внешние плагины. Эквивалент `--pure`. |
| `BOLT_SERVER_USERNAME` | Логин Basic Auth для `bolt serve` и `bolt web`. |
| `BOLT_SERVER_PASSWORD` | Пароль Basic Auth для `bolt serve` и `bolt web`. Все подключающиеся клиенты должны предоставить этот пароль. |
| `BOLT_CONFIG` | Переопределить путь к файлу конфигурации, который загружает Bolt. Bolt не будет искать в местах по умолчанию, если это задано. |
| `BOLT_CONFIG_DIR` | Переопределить каталог конфигурации. Bolt будет искать файлы конфигурации в этом каталоге вместо системного по умолчанию. |
| `BOLT_CONFIG_CONTENT` | Предоставить всю конфигурацию как inline-строку JSON. Полезно в CI, где неудобно писать файлы. Имеет наивысший приоритет среди источников конфигурации. |
| `BOLT_GIT_BASH_PATH` | Путь к каталогу `bin` в Git Bash на Windows, используется для поиска Unix-утилит вроде `less`. |

## API-ключи провайдеров

Bolt автоматически обнаруживает учётные данные провайдеров из переменных окружения — шаг `bolt providers login` не требуется. Каждый провайдер ищет свою переменную окружения, и Bolt использует её, если переменная установлена, вне зависимости от того, что хранится в `auth.json`.

<Tip>
  Устанавливайте API-ключи провайдеров в профиле shell (например, `~/.zshrc`, `~/.bashrc`) или в файле `.env`, загружаемом вашей оболочкой. Также на них можно ссылаться из файла конфигурации через синтаксис `${VAR_NAME}` в поле `provider.*.apiKey`, чтобы ключи никогда не хранились в открытом виде.
</Tip>

Распространённые переменные провайдеров:

| Переменная | Провайдер |
| --- | --- |
| `ANTHROPIC_API_KEY` | Anthropic (Claude) |
| `OPENAI_API_KEY` | OpenAI (GPT, o-series) |
| `GOOGLE_GENERATIVE_AI_API_KEY` | Google (Gemini) |
| `OPENROUTER_API_KEY` | OpenRouter |
| `AWS_ACCESS_KEY_ID` \+ `AWS_SECRET_ACCESS_KEY` | Amazon Bedrock |
| `AZURE_OPENAI_API_KEY` | Azure OpenAI |

Запустите `bolt models --verbose`, чтобы увидеть, какую переменную окружения ожидает каждый настроенный провайдер.

## Примеры использования

```bash
# Включить debug-логирование для одного запуска
BOLT_LOG_LEVEL=DEBUG bolt run "why is the auth test failing?"

# Запустить без плагинов, чтобы исключить их вмешательство
BOLT_PURE=1 bolt

# Запустить публичный сервер с Basic Auth
BOLT_SERVER_USERNAME=team BOLT_SERVER_PASSWORD=mysecret \
  bolt serve --hostname 0.0.0.0 --port 4096

# Передать конфигурацию inline (полезно в CI)
BOLT_CONFIG_CONTENT='{"model":"anthropic/claude-opus-4-5"}' \
  ANTHROPIC_API_KEY=sk-ant-xxx \
  bolt run "generate a changelog for this release"
```
