Bolt использует многослойную систему конфигурации: **глобальный** файл для настроек по умолчанию на уровне пользователя и **проектный** файл для параметров, специфичных для репозитория. Оба файла используют формат JSONC (JSON с комментариями) и оба автоматически создаются с указанием `$schema`, что включает автодополнение в редакторе.

## Расположение файлов конфигурации

### Проектная конфигурация

Создаётся автоматически при первом запуске внутри вашего проекта:

```text
<project-root>/.bolt/bolt.jsonc
```

Коммитьте этот файл, чтобы делиться конфигурацией провайдеров, MCP-серверами и пользовательскими инструкциями с остальной командой. Секретные учётные данные никогда не должны попадать сюда — используйте переменные окружения или глобальную конфигурацию.

### Глобальная конфигурация

Применяется ко всем проектам на вашей машине. Bolt ищет первый подходящий файл в системном каталоге конфигурации:

```text
# macOS / Linux
~/.config/bolt/bolt.jsonc   (предпочтительно)
~/.config/bolt/bolt.json

# Windows
%APPDATA%\bolt\bolt.jsonc
%APPDATA%\bolt\bolt.json
```

<Accordion title="Где находится глобальный каталог конфигурации?">
  Bolt следует XDG Base Directory Specification на Linux и macOS (`~/.config/bolt/`) и использует `%APPDATA%\bolt\` на Windows. Запустите `bolt debug config`, чтобы вывести полностью разрешённую конфигурацию на вашей машине.
</Accordion>

## Минимальный пример конфигурации

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    // Provider config goes here
  }
}
```

Поле `$schema` включает IntelliSense и валидацию в редакторах, поддерживающих JSON Schema. Bolt автоматически добавляет это поле, если оно отсутствует.

## Справочник по конфигурации

### `provider`

Настройте специфичные для провайдера параметры, такие как пользовательские базовые URL, региональные настройки или именованные учётные данные:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "provider": {
    "anthropic": {
      "name": "Anthropic"
    },
    "amazon-bedrock": {
      "options": {
        "region": "us-east-1"
      }
    }
  }
}
```

### `mcp`

Зарегистрируйте серверы [Model Context Protocol](https://modelcontextprotocol.io), которые агент может вызывать как инструменты:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "my-server": {
      "type": "local",
      "command": "node",
      "args": ["./mcp-server.js"],
      "env": {
        "DATABASE_URL": "$DATABASE_URL"
      }
    }
  }
}
```

Управляйте MCP-серверами интерактивно с помощью `bolt mcp add`, `bolt mcp list`, `bolt mcp auth` и `bolt mcp debug`.

### `instructions`

Добавьте пользовательские системные инструкции, которые вставляются в каждую сессию. Полезно для соблюдения соглашений по кодированию, гайдов по стилю или правил, специфичных для проекта:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "instructions": [
    "Always write tests alongside new code.",
    "Follow the Google TypeScript Style Guide.",
    "Never introduce new dependencies without explaining the trade-off."
  ]
}
```

Инструкции из нескольких файлов конфигурации (глобальный \+ проектный) объединяются и дедуплицируются автоматически.

### `plugin`

Загружайте плагины Bolt. Плагины могут добавлять новые инструменты, провайдеров, источники контекста и хуки:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "plugin": [
    "./plugins/my-tool.ts",
    "@my-org/bolt-plugin-jira"
  ]
}
```

### Удалённая конфигурация через `url`

Загружайте конфигурацию с удалённого URL при запуске. Полезно для централизованной командной конфигурации:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "url": "https://config.example.com/bolt-team.json",
  "headers": {
    "Authorization": "Bearer $TEAM_CONFIG_TOKEN"
  }
}
```

## Подстановка переменных

Значения в конфигурации могут ссылаться на переменные окружения с помощью синтаксиса `$VAR_NAME` или `${VAR_NAME}`. Подстановка происходит при загрузке, до парсинга конфигурации:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "database-tools": {
      "type": "local",
      "command": "npx",
      "args": ["db-mcp-server"],
      "env": {
        "DATABASE_URL": "$DATABASE_URL",
        "API_KEY": "${INTERNAL_API_KEY}"
      }
    }
  }
}
```

<Accordion title="Как использовать переменные окружения в конфигурации?">
  Ссылайтесь на любую переменную окружения с помощью `$VAR_NAME` или `${VAR_NAME}` в любом строковом значении конфигурации. Bolt подставляет значение при загрузке. Если переменная не установлена, используется буквальная строка `$VAR_NAME` — Bolt не выпадает без предупреждения и не выбрасывает ошибку при отсутствующих подстановках.
</Accordion>

## Переопределения через переменные окружения

Эти переменные окружения позволяют перенаправить или полностью переопределить конфигурацию, что удобно для CI, контейнеров и тестирования:

| Переменная | Описание |
| --- | --- |
| `BOLT_CONFIG` | Абсолютный путь к файлу конфигурации, загружаемому вместо проектного |
| `BOLT_CONFIG_DIR` | Переопределяет каталог, в котором Bolt ищет файлы конфигурации |
| `BOLT_CONFIG_CONTENT` | Предоставляет сырое содержимое JSONC-конфигурации как строку — файл не нужен |

`BOLT_CONFIG_CONTENT` особенно удобен в контейнеризованных окружениях, где монтировать файл неудобно:

```bash
export BOLT_CONFIG_CONTENT='{"provider":{"anthropic":{}}}'
bolt run "summarise the codebase"
```

<Accordion title="Какая конфигурация имеет приоритет, когда активны несколько источников?">
  Bolt объединяет конфигурации в этом порядке (более поздние записи побеждают):

  1. Глобальный файл конфигурации (`bolt.jsonc` / `bolt.json` в системном каталоге конфигурации)
  2. Удалённые конфигурации, загруженные по записям `url` в глобальной конфигурации
  3. Проектные файлы конфигурации (`.bolt/bolt.jsonc`, `.bolt/bolt.json`)
  4. Файл `BOLT_CONFIG` (если установлен)
  5. `BOLT_CONFIG_CONTENT` (если установлен)

  Массивы, такие как `instructions`, конкатенируются между источниками, а не заменяются. Объектные поля глубоко объединяются, при конфликтах побеждают более поздние значения.
</Accordion>
