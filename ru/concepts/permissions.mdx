Агенты Bolt могут читать файлы, писать файлы и выполнять shell-команды. Эти возможности ограничены двумя слоями: уровнем доступа для каждого агента и интерактивными запросами разрешений, которые вы можете одобрить, отклонить или настроить заранее.

## Уровни доступа агента

У каждого встроенного агента есть заявленный уровень доступа:

| Уровень доступа | Чтение файлов | Запись файлов | Выполнение shell-команд |
| --- | --- | --- | --- |
| **Full** | ✓ | ✓ | ✓ |
| **Edit** | ✓ | ✓ | ✗ |
| **Read** | ✓ | ✗ | ✗ |

Соответствие для встроенных агентов:

- **Full** — `code`, `debug`, `refactor`, `migrate`, `perf`
- **Edit** — `docs`
- **Read** — `plan`, `ask`, `code-review`, `security`

Переключайте агентов клавишей `Tab` в TUI или передавайте `--agent <name>` в `bolt run`.

## Интерактивные запросы

В рамках уровня доступа агента потенциально разрушительные действия всё ещё запрашивают подтверждение. Вы можете одобрить один раз, одобрить на сессию или отклонить. Отклонённые вызовы возвращают ошибку агенту, и он идёт дальше.

## Неинтерактивное одобрение

Для CI, скриптов или доверенных локальных рабочих процессов `bolt run` поддерживает флаги, пропускающие запросы:

```bash
bolt run --auto "tidy up imports"                   # автоодобрение всего, что не запрещено явно
bolt run --yolo "tidy up imports"                   # синоним --auto
bolt run --dangerously-skip-permissions "..."       # обход всех запросов
```

<Warning>
  `--auto`, `--yolo` и `--dangerously-skip-permissions` позволяют агенту читать, писать и выполнять без запросов. Используйте их только в доверенных окружениях.
</Warning>

## Правила уровня конфигурации

Вы можете заранее запретить (или заранее разрешить) конкретные инструменты для всего проекта, добавив блок `permission` в `.bolt/bolt.jsonc`. Это применяется к каждой сессии в проекте, включая неинтерактивные вызовы `bolt run`. См. схему в [Конфигурации](/concepts/configuration).
