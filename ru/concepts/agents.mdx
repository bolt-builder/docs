Bolt рассматривает каждую AI-персону как именованного **агента**: системный промпт в паре с точно ограниченным набором разрешений на инструменты. Вместо того чтобы запускать одну универсальную модель для каждой задачи, вы выбираете агента, чей доступ и фокус соответствуют тому, что вам нужно — будь то аудит безопасности, написание документации или сквозная миграция фреймворка.

## Уровни доступа

Каждому встроенному агенту присваивается один из трёх уровней доступа, определяющий, какие инструменты он может вызывать:

| Уровень | Предоставленные разрешения | Типичное применение |
|-------|---------------------|-------------|
| **Full** | Чтение файлов, запись/редактирование файлов, выполнение shell-команд | Активное программирование, отладка, рефакторинг, миграции |
| **Edit** | Чтение файлов, запись/редактирование файлов — без shell | Документация, обновление комментариев, безопасные правки текста |
| **Read** | Только чтение файлов — без записи и shell | Планирование, исследование, ревью кода, аудит |

## Встроенные агенты

Bolt поставляется с десятью специализированными агентами «из коробки». Переключайтесь между ними в TUI, нажимая <kbd>Tab</kbd>.

| Агент | Доступ | Описание |
|-------|--------|-------------|
| `code` | Full | По умолчанию: читает, пишет и запускает код |
| `plan` | Read | Исследует кодовую базу и формирует план без изменения кода |
| `ask` | Read | Вопросы и исследование — без правок файлов |
| `code-review` | Read | Проверяет изменения на корректность, стиль и безопасность |
| `debug` | Full | Отлаживает падающие тесты, крэши и логические ошибки |
| `refactor` | Full | Безопасный рефакторинг с верификацией тестами на каждом шаге |
| `docs` | Edit | Пишет и обновляет документацию и комментарии |
| `security` | Read | Аудит безопасности: уязвимости, секреты и опасные шаблоны |
| `migrate` | Full | Обновления фреймворков и миграции зависимостей |
| `perf` | Full | Анализ производительности и оптимизация |

## Субагенты

Помимо десяти основных агентов, Bolt предоставляет двух встроенных **субагентов**, которым основные агенты могут делегировать работу во время сессии. Вы никогда не выбираете субагента вручную — они запускаются автоматически, когда основной агент решает породить одного из них.

| Субагент | Роль |
|----------|------|
| `@general` | Делегирование сложных многошаговых задач, требующих широких возможностей |
| `@explore` | Быстрое исследование кодовой базы только для чтения — обходит файлы без побочных эффектов |

<Tip>
  Когда нужно быстро разобраться в незнакомой кодовой базе, начните с агента `ask` или `plan`. За кулисами они могут запустить субагента `@explore`, чтобы на большой скорости проиндексировать проект перед формированием ответа — не трогая ни одного файла.
</Tip>

## Переключение агентов

**В TUI** — нажмите <kbd>Tab</kbd>, чтобы циклически перебрать список доступных агентов в любой момент сессии. Активный агент показан в подвале сессии.

**Неинтерактивно** — передайте `--agent <name>` в `bolt run`, чтобы закрепить конкретного агента на время этого запуска:

```bash
bolt run --agent ask "what does the authentication flow do?"
bolt run --agent security "audit the API layer for injection vulnerabilities"
bolt run --agent docs "add JSDoc comments to every exported function in src/utils"
```

## Список агентов

Чтобы увидеть все доступные агенты — как встроенные, так и пользовательские — с их режимами и конфигурацией разрешений:

```bash
bolt agent list
```

## Пользовательские агенты

Собственных агентов можно создать двумя способами.

### Генерация через `bolt agent create`

Интерактивный мастер генерирует файл агента с помощью LLM и записывает его на диск:

```bash
bolt agent create
```

Все флаги опциональны. Указывайте их, чтобы запустить неинтерактивно:

```bash
bolt agent create \
  --description "Audit GraphQL resolvers for N+1 problems and suggest DataLoader fixes" \
  --path .bolt/agents \
  --mode primary \
  --permissions read,grep,glob \
  --model anthropic/claude-opus-4-5
```

| Флаг | Описание |
|------|-------------|
| `--description` | Что должен делать агент (используется как промпт для LLM при генерации) |
| `--path` | Каталог, в который будет записан сгенерированный файл агента |
| `--mode` | `all` (по умолчанию), `primary` или `subagent` |
| `--permissions` | Список разрешений через запятую. Опустите для всех. |
| `--model` / `-m` | Модель в формате `provider/model` |

### Написать markdown-файл вручную

Агент — это просто markdown-файл с YAML-frontmatter. Поместите его в `.bolt/agents/` внутри проекта или в глобальный каталог агентов:

```markdown
---
description: "Audit GraphQL resolvers for N+1 problems"
mode: primary
permission:
  bash: deny
  edit: deny
---

You are a GraphQL performance specialist. Your job is to identify N+1 query
patterns in resolver code and recommend DataLoader-based solutions...
```

Имя файла (без `.md`) становится идентификатором агента.

### Доступные разрешения

Разрешения — это тонкие «шлюзы» инструментов, которыми вы управляете при создании пользовательского агента:

| Разрешение | Управляет |
|------------|----------|
| `bash` | Выполнение shell-команд |
| `read` | Чтение файлов |
| `edit` | Запись и редактирование файлов (также контролирует `write` и `apply_patch`) |
| `glob` | Перечисление файлов по glob/каталогов |
| `grep` | Поиск в файлах через ripgrep |
| `webfetch` | HTTP-запросы к вебу |
| `task` | Запуск подзадач субагентов |
| `todowrite` | Создание и обновление задач |
| `websearch` | Поисковые запросы в вебе |
| `lsp` | Операции Language Server Protocol |
| `skill` | Доступ к навыкам проекта |
