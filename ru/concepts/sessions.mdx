**Сессия** — это основная единица работы в Bolt. Каждый промпт, который вы отправляете, каждый файл, который агент читает или редактирует, и каждый вызов инструмента моделью надёжно записываются в историю этой сессии. Поскольку сессии живут в локальной базе данных SQLite, они переживают перезапуски процесса, могут быть просмотрены и запрошены в любое время и никогда не покидают вашу машину, если только вы явно не поделитесь ими или не экспортируете их.

<Note>
  Все данные сессии хранятся локально в базе данных SQLite на вашей машине. Ничто не отправляется на внешние серверы, если вы не включите шаринг. Используйте `bolt db path`, чтобы найти точный файл базы данных.
</Note>

## Жизненный цикл сессии

Сессия начинается в момент отправки первого промпта и заканчивается только когда вы её удаляете. Между этими двумя точками вы можете свободно отсоединяться, продолжать, ветвиться или передавать её.

<Steps>
  <Step title="Создание или продолжение сессии">
    Запустите TUI, чтобы начать новую сессию интерактивно, или передайте промпт в `bolt run`, чтобы создать её неинтерактивно:

    ```bash
    # Новая сессия в TUI
    bolt

    # Новая сессия неинтерактивно
    bolt run "add error handling to the payment service"
    ```
  </Step>
  <Step title="Отсоединитесь и вернитесь позже">
    Закройте TUI в любой момент — сессия сохранится автоматически. Возобновите последнюю сессию с `--continue` или укажите конкретную сессию по ID с `--session`:

    ```bash
    # Возобновить последнюю сессию
    bolt run --continue "now write the tests too"

    # Возобновить конкретную сессию
    bolt run --session ses_abc123 "continue from where we left off"
    ```
  </Step>
  <Step title="Форк перед экспериментом">
    Используйте `--fork`, чтобы ответвиться от текущей истории сессии перед рискованным изменением. Форк — независимая сессия, не затрагивающая оригинал:

    ```bash
    bolt run --continue --fork "try rewriting this with a functional approach"
    ```
  </Step>
  <Step title="Поделитесь и сотрудничайте">
    Сгенерируйте URL для шаринга с `--share`. Любой, у кого есть ссылка, сможет просмотреть стенограмму сессии в браузере:

    ```bash
    bolt run --share --continue "final pass — clean up the diff"
    ```
  </Step>
</Steps>

## Команды управления сессиями

### Список сессий

```bash
bolt session list
```

Выводит отформатированную таблицу всех сессий с их ID, названием и временем последнего обновления. Добавьте `--format json`, чтобы получить машиночитаемый вывод, или `-n <N>`, чтобы ограничить последними N сессиями:

```bash
bolt session list --format json
bolt session list -n 10
```

### Удаление сессии

```bash
bolt session delete <sessionID>
```

Безвозвратно удаляет сессию и все её сообщения из локальной базы данных.

## Флаги `run` для управления сессией

Эти флаги доступны в `bolt run`:

| Флаг | Синоним | Описание |
|------|-------|-------------|
| `--continue` | `-c` | Продолжить последнюю сессию |
| `--session <id>` | `-s` | Продолжить конкретную сессию по ID |
| `--fork` | | Форкнуть сессию перед продолжением (требует `--continue` или `--session`) |
| `--share` | | Сгенерировать URL для шаринга сессии |
| `--title <title>` | | Установить или переопределить название сессии |

## Экспорт сессий

Экспортируйте полную стенограмму сессии как JSON:

```bash
# Экспорт последней сессии
bolt export

# Экспорт конкретной сессии
bolt export <sessionID>

# Экспорт с редактированием чувствительных данных
bolt export --sanitize > transcript.json
```

Флаг `--sanitize` заменяет пути к файлам, содержимое кода, входные и выходные данные инструментов и другие потенциально чувствительные поля плейсхолдерами `[redacted:kind:id]` — полезно для обмена стенограммами с товарищами по команде или отправки багрепортов.

## Импорт сессий

Импортируйте сессию из локального JSON-файла или напрямую из URL шаринга:

```bash
# Из локального файла
bolt import ./transcript.json

# Из URL шаринга
bolt import https://opncd.ai/share/abc123
```

Импортированные сессии появляются в вашем локальном списке сессий и полностью пригодны к возобновлению.

## Запросы к базе данных сессий

Bolt открывает базовую SQLite-базу данных напрямую для опытных пользователей.

```bash
# Показать путь к файлу базы данных
bolt db path

# Открыть интерактивную SQLite-оболочку
bolt db

# Выполнить одноразовый запрос
bolt db "SELECT id, title, time_updated FROM session ORDER BY time_updated DESC LIMIT 5"
```

По умолчанию формат вывода — значения, разделённые табуляцией; добавьте `--format json` для вывода в JSON.

## Использование токенов и статистика стоимости

`bolt stats` агрегирует данные об использовании токенов и стоимости по всем вашим сессиям:

```bash
# Статистика за всё время
bolt stats

# Последние 7 дней
bolt stats --days 7

# Только текущий проект
bolt stats --project ""

# Показать разбивку по моделям (топ 5 моделей)
bolt stats --models 5

# Ограничить таблицу использования инструментов топ-10
bolt stats --tools 10
```

Вывод включает общее число сессий, сообщений, входные/выходные токены/токены рассуждений/кэша, общую стоимость, среднюю стоимость в день, средние и медианные токены на сессию и разбивку использования инструментов. Передайте `--models`, чтобы также показать разбивку сообщений, токенов и стоимости по моделям.

## Рабочий процесс форка и шаринга

Вот полный пример форка сессии и шаринга результата:

<Steps>
  <Step title="Начните работу в новой сессии">
    ```bash
    bolt run "refactor the UserService to use dependency injection"
    ```
  </Step>
  <Step title="Форкните перед рискованным следующим шагом">
    ```bash
    bolt run --continue --fork "also migrate it to the new Repository pattern"
    ```

    ID форкнутой сессии выводится в консоль. Оригинальная сессия не затрагивается.
  </Step>
  <Step title="Поделитесь форком для ревью">
    ```bash
    bolt run --session <forked-id> --share "final cleanup and comments"
    ```

    URL для шаринга выводится, как только сессия становится idle.
  </Step>
  <Step title="Импортируйте на другой машине">
    ```bash
    bolt import https://opncd.ai/share/<slug>
    ```
  </Step>
</Steps>
