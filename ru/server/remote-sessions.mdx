У Bolt есть встроенный HTTP-сервер, полностью отвязывающий движок от интерфейса. Вы можете запустить headless-сервер на мощной удалённой машине (облачной VM, dev-контейнере, десктопе, оставленном на ночь) и подключать TUI со своего ноутбука, второго терминала или даже браузера — все указывают на одну и ту же живую сессию. Это делает Bolt подходящим для команд, удалённых рабочих нагрузок и долгих задач, за которыми хочется присматривать, не заходя по SSH.

## `bolt serve`

Запускает headless-сервер Bolt, выставляющий полный API по HTTP и принимающий подключения TUI.

```bash
bolt serve
```

### Флаги

| Флаг | По умолчанию | Описание |
|------|---------|-------------|
| `--hostname <host>` | `127.0.0.1` | Hostname или IP-адрес для привязки |
| `--port <n>` | `0` (авто) | Порт для прослушивания; Bolt печатает назначенный порт при запуске |
| `--mdns` | `false` | Анонс сервера через mDNS для zero-config обнаружения в локальной сети; также задаёт hostname `0.0.0.0` |
| `--mdns-domain <name>` | `opencode.local` | Пользовательский mDNS service domain |
| `--cors <origin>` | `[]` | Дополнительные origin для разрешения через CORS (можно повторять) |

<Warning>
  Если `OPENCODE_SERVER_PASSWORD` не установлен, Bolt печатает предупреждение, а сервер полностью открыт для всех, кто может к нему достучаться. Всегда устанавливайте пароль перед привязкой к любому интерфейсу, отличному от `127.0.0.1`.
</Warning>

### Аутентификация

Защитите сервер HTTP Basic Auth через переменные окружения:

| Переменная | Описание |
|----------|-------------|
| `OPENCODE_SERVER_PASSWORD` | Пароль Basic Auth |
| `OPENCODE_SERVER_USERNAME` | Логин Basic Auth (по умолчанию `opencode`, если не задан) |

```bash
OPENCODE_SERVER_PASSWORD=my-secret bolt serve --hostname 0.0.0.0 --port 4096
```

## `bolt attach <url>`

Подключить полный TUI к работающему серверу Bolt. Работает с любым сервером, доступным по HTTP, — локальным или удалённым.

```bash
bolt attach http://my-dev-machine.local:4096
```

### Флаги

| Флаг | Синоним | Описание |
|------|-------|-------------|
| `--dir <path>` | | Каталог для запуска на удалённом сервере |
| `--continue` | `-c` | Продолжить последнюю сессию на сервере |
| `--session <id>` | `-s` | ID сессии для продолжения |
| `--fork` | | Форкнуть сессию при продолжении (используйте с `--continue` или `--session`) |
| `--password <pw>` | `-p` | Пароль Basic Auth (переопределяет `OPENCODE_SERVER_PASSWORD`) |
| `--username <user>` | `-u` | Логин Basic Auth (переопределяет `OPENCODE_SERVER_USERNAME`) |
| `--mini` | | Использовать минимальный интерактивный UI вместо полного TUI |

```bash
# Продолжить последнюю сессию на удалённом сервере
bolt attach http://10.0.0.5:4096 --continue --password my-secret

# Форкнуть конкретную сессию
bolt attach http://10.0.0.5:4096 --session ses_abc123 --fork

# Минимальный UI — полезно в ограниченных терминалах
bolt attach http://10.0.0.5:4096 --mini
```

## `bolt web`

Запустить сервер Bolt и сразу открыть веб-UI в браузере по умолчанию. Это самый быстрый способ получить браузерный интерфейс локально.

```bash
bolt web
```

`bolt web` принимает те же сетевые флаги, что и `bolt serve`.

## Обнаружение через mDNS

Передайте `--mdns` в `bolt serve`, чтобы транслировать адрес сервера в локальную сеть через mDNS. Любая машина в той же сети сможет подключиться по mDNS hostname, не зная IP-адреса или порта.

```bash
# На машине сервера
OPENCODE_SERVER_PASSWORD=my-secret bolt serve --mdns

# С другой машины в той же LAN
bolt attach http://opencode.local --password my-secret
```

mDNS домен по умолчанию — `opencode.local`. Переопределите его через `--mdns-domain`:

```bash
bolt serve --mdns --mdns-domain mydevbox.local
```

## Запуск сервера и удалённое подключение

<Steps>
  <Step title="Установите пароль на серверной машине">
    Экспортируйте `OPENCODE_SERVER_PASSWORD` перед запуском сервера. Без него Bolt печатает предупреждение, и API остаётся без аутентификации.

    ```bash
    export OPENCODE_SERVER_PASSWORD=my-secret
    ```
  </Step>

  <Step title="Запустите headless-сервер">
    Привяжитесь ко всем интерфейсам, чтобы ноутбук мог достучаться, и опционально выберите фиксированный порт:

    ```bash
    bolt serve --hostname 0.0.0.0 --port 4096
    # opencode server listening on http://0.0.0.0:4096
    ```

    Оставьте этот терминал открытым (или запустите в `tmux` / `screen` / systemd-юните).
  </Step>

  <Step title="Подключитесь с ноутбука">
    С любой машины, которая может достучаться до сервера, запустите:

    ```bash
    bolt attach http://192.168.1.10:4096 --password my-secret
    ```

    Полный TUI открывается и подключается к удалённому движку. Сессии, история и состояние инструментов живут на сервере.
  </Step>

  <Step title="Продолжите сессию позже">
    Отсоединитесь, выйдя из TUI (`q` или `Ctrl-C`). Сессия продолжает работать на сервере. Чтобы вернуться:

    ```bash
    bolt attach http://192.168.1.10:4096 --continue --password my-secret
    ```

    Или форкните её, чтобы ответвиться, не затрагивая оригинал:

    ```bash
    bolt attach http://192.168.1.10:4096 --continue --fork --password my-secret
    ```
  </Step>
</Steps>

## Пример удалённого рабочего процесса

Распространённый паттерн — оставлять сервер Bolt на многоядерной dev-машине и подключаться с тонкого ноутбука.

```
┌──────────────────────────────────────────────────┐
│  Dev machine (powerful, stays on)                │
│                                                  │
│  $ OPENCODE_SERVER_PASSWORD=secret bolt serve \  │
│      --hostname 0.0.0.0 --port 4096              │
│                                                  │
│  opencode server listening on http://0.0.0.0:4096│
└──────────────────────────────────────────────────┘
               ↑  HTTP (LAN / VPN / SSH tunnel)
┌──────────────────────────────────────────────────┐
│  Laptop                                          │
│                                                  │
│  $ bolt attach http://dev-machine:4096 \         │
│      --password secret                           │
└──────────────────────────────────────────────────┘
```

Все данные сессии хранятся в базе SQLite на сервере. Ноутбук лишь отрисовывает TUI — он может отсоединяться и переподключаться в любое время без потери работы.
