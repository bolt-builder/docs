Плагины позволяют расширять Bolt за пределы встроенных возможностей. Плагин — это модуль Node или Bun, экспортирующий манифест плагина Bolt; при загрузке он может регистрировать новых LLM-провайдеров, пользовательские методы аутентификации, дополнительные инструменты и адаптеры рабочих пространств. Плагины можно установить для одного проекта или применять глобально ко всей вашей работе.

## Установка плагина

Используйте `bolt plugin install` (синоним: `bolt plug`) для установки плагина из npm и автоматической регистрации его в конфигурации:

```bash
bolt plugin install <module>
```

### Флаги

| Флаг | Синоним | Описание |
|------|-------|-------------|
| `--global` | `-g` | Установить в глобальную конфигурацию вместо текущего проекта |
| `--force` | `-f` | Заменить существующую запись для того же модуля |

### Область: проект или глобально

По умолчанию `bolt plugin install` добавляет плагин в проектный `.bolt/bolt.jsonc`. Передайте `--global`, чтобы добавить его в конфигурацию уровня пользователя, тогда он будет загружаться в каждом проекте.

```bash
# Проектная область (по умолчанию)
bolt plugin install @acme/bolt-plugin-jira

# Глобально — загружается в каждом проекте
bolt plugin install @acme/bolt-plugin-jira --global
```

<Note>
  Запустите `bolt --pure` (или установите `OPENCODE_PURE=1`), чтобы запустить Bolt с полностью отключёнными внешними плагинами. Полезно для отладки, вызывает ли плагин неожиданное поведение, без удаления плагина.
</Note>

## Установка опубликованного плагина

<Steps>
  <Step title="Найдите пакет плагина">
    Поищите в npm пакеты со словами `bolt-plugin` или `opencode-plugin` в имени, либо перейдите по ссылке из документации провайдера.
  </Step>

  <Step title="Установите в свой проект">
    ```bash
    bolt plugin install @acme/bolt-plugin-jira
    ```

    Bolt устанавливает пакет, читает его манифест для обнаружения серверных и TUI-целей, затем записывает запись в `.bolt/bolt.jsonc`.
  </Step>

  <Step title="Проверьте конфигурацию">
    Откройте `.bolt/bolt.jsonc` и подтвердите, что запись плагина добавлена:

    ```jsonc
    {
      "plugin": [
        "@acme/bolt-plugin-jira"
      ]
    }
    ```
  </Step>

  <Step title="Запустите сессию">
    ```bash
    bolt
    ```

    Bolt загружает плагин при запуске. Все провайдеры или инструменты, которые он регистрирует, сразу становятся доступными.
  </Step>
</Steps>

## Ручная настройка плагина

Вы можете регистрировать плагины, редактируя `.bolt/bolt.jsonc` напрямую. Это полезно для локальных плагинов в разработке:

```jsonc
{
  "plugin": [
    "./plugins/my-plugin.ts"
  ]
}
```

Относительные пути разрешаются от корня проекта. Поддерживаются как TypeScript, так и JavaScript в качестве точек входа.

## Создание плагина

Плагины пишутся под пакет `@opencode-ai/plugin`, который предоставляет интерфейс `Hooks`, которому должен соответствовать ваш модуль.

```bash
npm install --save-dev @opencode-ai/plugin
```

Минимальный плагин экспортирует функцию, которая получает объект `PluginInput` и возвращает объект `Hooks`:

```typescript
import type { Plugin } from "@opencode-ai/plugin"

const myPlugin: Plugin = async (input) => {
  return {
    // auth hook — register custom authentication methods
    auth: {
      methods: [
        {
          id: "my-provider-auth",
          name: "My Provider",
          // ... provider-specific fields
        },
      ],
    },
  }
}

export default myPlugin
```

### Доступные типы хуков

| Хук | Назначение |
|------|---------|
| `auth` | Регистрация пользовательских провайдеров аутентификации с массивом `methods` |
| `event` | Реакция на события сессии (сообщения, вызовы инструментов, завершения) |
| `config` | Реакция на изменения конфигурации во время выполнения |
| `dispose` | Очистка ресурсов при выгрузке плагина |

Объект `PluginInput` предоставляет `client` (типизированный API-клиент Bolt), `project`, `worktree`, `directory` и `serverUrl`, чтобы ваш плагин мог взаимодействовать с работающим сервером.
