Пользовательские инструменты позволяют вам представить всё, что можно заскриптовать (shell-скрипты, программы на Node/Bun/Python, небольшие бинарные файлы), как инструмент, который агент может вызвать по имени. Это самый простой способ дать Bolt доступ к рабочим процессам сборки, деплоя или данных вашего проекта.

## Где они живут

Кладите файлы в один из каталогов:

- `.opencode/tool/` — привязан к проекту, коммитится вместе с репозиторием.
- `.opencode/tools/` — принимается как синоним предыдущего.

Каждый файл становится инструментом, названным по имени файла (без расширения). Инструменты подхватываются автоматически при следующем запуске Bolt.

## Анатомия инструмента

Пользовательский инструмент объявляет своё имя, описание и схему входных данных в заголовке, затем реализует поведение. Точная форма зависит от выбранного вами рантайма (shell-скрипт, TypeScript и т. д.), но каждый инструмент должен:

1. Публиковать JSON Schema для своих входных данных, чтобы модель знала, как его вызывать.
2. Возвращать значение (или ошибку), которое Bolt может отрендерить в TUI и передать обратно модели.

После загрузки инструмент появляется в списке инструментов агента рядом со встроенными вроде `bash` и `grep` и контролируется той же системой [разрешений](/concepts/permissions).

## Когда использовать пользовательский инструмент против MCP-сервера

- **Пользовательский инструмент** — маленький, специфичный для проекта, без переиспользования между проектами. Быстро писать.
- **MCP-сервер** — общий для нескольких проектов или оборачивающий реальный внешний сервис с аутентификацией. См. [MCP-серверы](/extending/mcp-servers).
- **Инструмент плагина** — распространяется как npm-пакет наряду с другими точками расширения. См. [Плагины](/extending/plugins).
