Model Context Protocol (MCP) — открытый стандарт, позволяющий AI-агентам взаимодействовать с внешними инструментами и источниками данных через общий интерфейс. Bolt использует MCP, чтобы расширить возможности агентов — подключённый MCP-сервер может предоставлять что угодно, от инструмента запросов к базе данных до полноценного веб-поискового API. Bolt управляет полным жизненным циклом: добавляет серверы, проводит OAuth-потоки, обновляет токены и проверяет связность.

## Типы серверов

Bolt поддерживает два вида MCP-серверов.

| Тип | Транспорт | Описание |
|------|-----------|-------------|
| `remote` | HTTP / SSE (Streamable HTTP) | Сервер, работающий на URL, доступном по сети |
| `local` | stdio | Локальная команда, которую Bolt порождает как дочерний процесс |

Удалённые серверы поддерживают OAuth-аутентификацию из коробки. Bolt обрабатывает получение, хранение и автоматическое обновление токенов — вы никогда не управляете токенами вручную.

## Команды

### `bolt mcp add`

Добавьте новый MCP-сервер интерактивно или одной командой.

**Интерактивно** — запустите `bolt mcp add` без аргументов, чтобы пройти мастер с подсказками, который спросит имя, область (проект или глобально), тип, URL или команду и использует ли сервер OAuth.

**Неинтерактивно** — укажите имя плюс либо `--url` для удалённого сервера, либо команду после `--` для локального:

<CodeGroup>

```bash Remote server
bolt mcp add my-server --url https://my-mcp-server.example.com/mcp
```

```bash Remote server with OAuth credentials
bolt mcp add my-server --url https://my-mcp-server.example.com/mcp
# OAuth prompts appear in the interactive flow
```

```bash Local stdio server
bolt mcp add filesystem -- npx -y @modelcontextprotocol/server-filesystem /tmp
```

```bash Remote server with custom HTTP headers
bolt mcp add my-server --url https://my-mcp-server.example.com/mcp \
  --header "Authorization=Bearer sk-abc123"
```

</CodeGroup>

**Флаги для `bolt mcp add`**

| Флаг | Описание |
|------|-------------|
| `--url <url>` | URL удалённого MCP-сервера |
| `--header <KEY=VALUE>` | HTTP-заголовок для отправки удалённому серверу (можно повторять) |
| `--env <KEY=VALUE>` | Переменная окружения для локального сервера (можно повторять) |

### `bolt mcp list`

Показать все настроенные MCP-серверы вместе со статусом подключения и аутентификации.

```bash
bolt mcp list
```

Каждая запись показывает иконку статуса:

| Иконка | Значение |
|------|---------|
| `✓` | Подключён (и аутентифицирован, если используется OAuth) |
| `⚠` | Нужна аутентификация или учётные данные истекли |
| `✗` | Не удалось подключиться или требуется регистрация клиента |
| `○` | Ещё не инициализирован или отключён |

---

### `bolt mcp auth <name>`

Аутентифицируйтесь на удалённом MCP-сервере с OAuth. Если вы опустите имя, Bolt покажет интерактивный выбор, перечисляющий все OAuth-совместимые серверы вместе с их текущим статусом аутентификации (`✓ authenticated`, `⚠ expired`, `✗ not authenticated`).

```bash
# Аутентифицировать конкретный сервер
bolt mcp auth my-server

# Выбрать из списка OAuth-совместимых серверов
bolt mcp auth
```

Bolt открывает ваш браузер по URL авторизации провайдера и ждёт callback — полный OAuth-хендшейк, включая динамическую регистрацию клиента при необходимости, происходит автоматически.

<Note>
  Bolt обрабатывает полный OAuth-поток, включая хранение токенов и автоматическое обновление. Вам не нужно копировать токены или управлять их истечением вручную. Если сервер требует предзарегистрированный client ID, добавьте `oauth.clientId` (и опционально `oauth.clientSecret`) в запись конфигурации сервера в `.bolt/bolt.jsonc`.
</Note>

---

### `bolt mcp logout <name>`

Удалить сохранённые OAuth-учётные данные для сервера. Если опустить имя, Bolt предложит выбрать из списка серверов, у которых есть сохранённые токены.

```bash
bolt mcp logout my-server
```

---

### `bolt mcp debug <name>`

Проверить связность удалённого сервера и просмотреть его состояние OAuth без запуска полной сессии. Это первый инструмент, к которому стоит обратиться, когда сервер показывает `✗ failed` или `⚠ needs authentication`.

```bash
bolt mcp debug my-server
```

`debug` сообщает:
- URL сервера и текущий статус аутентификации
- Детали access-токена (замаскированные) и время его истечения
- Присутствует ли refresh-токен
- Сырой HTTP-код ответа сервера
- Содержимое заголовка `WWW-Authenticate`
- Результат проверки OAuth discovery (без завершения потока)

## Ручная конфигурация

Вы можете добавлять или редактировать MCP-серверы напрямую в `.bolt/bolt.jsonc`, не используя команды CLI. Bolt подхватит изменения при следующем запуске сессии.

```jsonc
{
  "mcp": {
    "my-server": {
      "type": "remote",
      "url": "https://my-mcp-server.example.com/mcp"
    }
  }
}
```

Локальный stdio-сервер выглядит так:

```jsonc
{
  "mcp": {
    "filesystem": {
      "type": "local",
      "command": ["npx", "-y", "@modelcontextprotocol/server-filesystem", "/tmp"]
    }
  }
}
```

Чтобы задать пользовательские HTTP-заголовки или отключить OAuth на удалённом сервере:

```jsonc
{
  "mcp": {
    "my-server": {
      "type": "remote",
      "url": "https://my-mcp-server.example.com/mcp",
      "headers": {
        "Authorization": "Bearer sk-abc123"
      },
      "oauth": false
    }
  }
}
```

## Добавление и аутентификация удалённого MCP-сервера

<Steps>
  <Step title="Добавьте сервер">
    Запустите `bolt mcp add` и следуйте подсказкам, либо используйте неинтерактивную форму:

    ```bash
    bolt mcp add my-server --url https://my-mcp-server.example.com/mcp
    ```

    Bolt запишет запись в `.bolt/bolt.jsonc` (проектная область) или в вашу глобальную конфигурацию.
  </Step>

  <Step title="Проверьте статус подключения">
    ```bash
    bolt mcp list
    ```

    Если сервер требует аутентификации, рядом с его именем будет `⚠ needs authentication`.
  </Step>

  <Step title="Аутентифицируйтесь через OAuth">
    ```bash
    bolt mcp auth my-server
    ```

    Bolt откроет ваш браузер. После одобрения доступа терминал подтвердит успешную аутентификацию, и статус сервера сменится на `✓ connected (OAuth)`.
  </Step>

  <Step title="Проверьте, что инструменты доступны">
    Запустите сессию Bolt. Инструменты, предоставляемые сервером, теперь доступны всем агентам. В любой момент их можно проверить:

    ```bash
    bolt mcp debug my-server
    ```
  </Step>
</Steps>
