O Bolt vem com quatro comandos que conectam seu fluxo de trabalho diário do Git à IA: um agente do GitHub Actions que você pode instalar com um único comando, um atalho para fazer checkout de pull requests, um gerador de mensagens de commit com IA e um revisor de código com IA com códigos de saída legíveis por máquina. Juntos, eles permitem trazer o Bolt para cada estágio do desenvolvimento — codificação local, revisão de PR e integração contínua.

---

## `bolt github`

Gerencia o agente do GitHub Actions que executa o Bolt em eventos de CI.

### `bolt github install`

Instala o workflow do GitHub Actions no repositório atual. Isso grava o YAML do workflow em `.github/workflows/` para que o Bolt inicie automaticamente em comentários de issue, novos pull requests ou outros eventos que você configurar.

```bash
bolt github install
```

Execute isso a partir da raiz de um repositório git. Você precisará de acesso de escrita a `.github/workflows/`.

### `bolt github run`

Execute o agente do GitHub localmente ou dentro de uma etapa de CI, reproduzindo um payload de evento específico do GitHub.

```bash
bolt github run --event <event> --token <pat>
```

| Flag | Descrição |
|------|-------------|
| `--event <event>` | Nome do evento GitHub ou caminho para um payload JSON de evento |
| `--token <pat>` | Token de acesso pessoal do GitHub (`github_pat_…`) usado para postar comentários e buscar contexto |

## Configurar o agente do GitHub Actions

<Steps>
  <Step title="Instale o workflow">
    A partir da raiz do seu repositório:

    ```bash
    bolt github install
    ```

    O Bolt grava um arquivo de workflow do GitHub Actions em `.github/workflows/`. Faça commit e push do arquivo.
  </Step>

  <Step title="Adicione sua chave de API como secret">
    Nas configurações do seu repositório, adicione a chave de API do seu provedor de LLM preferido como um secret de repositório (por exemplo, `ANTHROPIC_API_KEY`). O workflow a capturará automaticamente.
  </Step>

  <Step title="Dispare o agente">
    Comente `/bolt <sua solicitação>` em qualquer issue ou pull request. O workflow dispara, o Bolt lê o payload do evento e posta uma resposta com o resultado.
  </Step>

  <Step title="Execute localmente para depuração">
    Reproduza um payload de evento ao vivo de uma execução de workflow anterior:

    ```bash
    bolt github run \
      --event path/to/event.json \
      --token github_pat_abc123
    ```
  </Step>
</Steps>

## `bolt pr <number>`

Faz checkout de um pull request do GitHub em um branch local e inicia o Bolt nesse branch — pronto para revisar, depurar ou continuar o trabalho de onde o autor do PR parou.

```bash
bolt pr 42
```

O Bolt usa o CLI `gh` para buscar o PR, cria um branch chamado `pr/<number>` e conecta a referência de tracking upstream. Para PRs entre repositórios (fork), ele adiciona o fork como remote automaticamente. Se a descrição do PR contiver uma URL de sessão Bolt compartilhada (`opncd.ai/s/…`), a sessão é importada para que você possa continuar a conversa do autor.

> Requer o [GitHub CLI (`gh`)](https://cli.github.com/) instalado e autenticado.

## `bolt commit`

Gera uma mensagem de commit a partir de suas alterações staged (ou todas rastreadas) e faz commit em um único passo.

```bash
bolt commit
```

O Bolt faz o diff das suas alterações, alimenta o diff ao agente `commit` junto com os assuntos de commit recentes para referência de estilo e executa `git commit -m <message>` com o resultado.

### Flags

| Flag | Alias | Descrição |
|------|-------|-------------|
| `--all` | `-a` | Faz commit de todas as alterações rastreadas, não apenas das staged (equivalente a `git commit -a`) |
| `--dry-run` | | Imprime a mensagem gerada sem fazer commit |
| `--model <provider/model>` | `-m` | Sobrescreve o modelo usado para gerar a mensagem |

```bash
# Stage everything and commit
bolt commit --all

# Preview the message without committing
bolt commit --dry-run

# Use a specific model
bolt commit --model anthropic/claude-opus-4-5
```

<Tip>
  Use `bolt commit --dry-run` para pré-visualizar a mensagem gerada antes de fazer commit. Se você quiser editá-la, copie a saída e execute `git commit -m "…"` com sua redação ajustada.
</Tip>

## `bolt review`

Executa o agente `code-review` contra um diff e sai com um veredito legível por máquina. A linha final da revisão é sempre `Verdict: PASS` ou `Verdict: FAIL`, tornando `bolt review` pronto para pipelines de CI.

```bash
bolt review
```

Por padrão, `bolt review` faz o diff de `HEAD` contra a árvore de trabalho. Use as flags abaixo para delimitar o diff.

### Flags

| Flag | Alias | Descrição |
|------|-------|-------------|
| `--staged` | | Revisa apenas as alterações staged |
| `--branch <name>` | | Revisa alterações desde o merge base com o branch nomeado (padrão: branch padrão do repositório) |
| `--model <provider/model>` | `-m` | Modelo a usar para a revisão |

### Códigos de saída

| Código | Significado |
|------|---------|
| `0` | `Verdict: PASS` — nenhuma questão crítica ou grave |
| `1` | `Verdict: FAIL` — uma ou mais questões críticas ou graves encontradas |
| `2` | Veredito não pôde ser determinado a partir da resposta |

### Uso em um workflow do GitHub Actions

```yaml
name: AI Code Review
on:
  pull_request:
    branches: [main]

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Install Bolt
        run: curl -fsSL https://raw.githubusercontent.com/bolt-builder/bolt-cli/dev/install | bash

      - name: AI review
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: bolt review --branch main
```

Um código de saída diferente de zero faz falhar o check, bloqueando o merge até que os problemas sejam resolvidos.

<Tip>
  Execute `bolt review --staged` antes de fazer commit para capturar problemas enquanto ainda são fáceis de mudar — antes que cheguem a um pull request.
</Tip>
