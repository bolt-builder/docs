项目记忆使 Bolt 感觉像是它已经了解你的项目。每当一个会话结束一轮时，Bolt 会提炼有用的信息并将其写入按项目的记忆存储。当你打开新会话时，Bolt 会把记忆索引以及最近的会话摘要注入到系统提示中，让代理带着真正的上下文而非空白开始。

## 捕获是如何工作的

在每一轮对话结束时，Bolt 会请模型总结那些对下一次有用的持久事实：约定、架构注释、文件布局、构建/测试命令、坑点和未完成的话题。这些内容会被写入磁盘上项目的记忆目录，同时保留最近会话的滚动摘要。

记忆是按项目隔离的。同一台机器上对同一仓库的两次 checkout 会共享记忆；无关的项目彼此之间看不到记忆。

## 显式工具

代理也可以在会话中直接读写记忆：

- `memory_save` — 记录一个代理下次应记住的具体事实。
- `memory_recall` — 查询代理（或你）先前捕获的内容。

你可以对代理说“记住我们用 pnpm，不用 npm”，它会替你调用 `memory_save`。

## 按会话控制

在 TUI 中，你可以通过斜杠命令切换当前会话的记忆行为：

```text
/memory use on|off         # 本会话是否读取项目记忆
/memory contribute on|off  # 本会话是否回写到记忆
```

这在你希望进行不污染记忆的一次性探索会话时很有用，或者用于仍能从先前上下文中受益的只读会话。

## 查看和编辑记忆

```bash
bolt memory           # 查看当前项目的记忆存储
```

记忆以纯文本文件形式存储在项目的 Bolt 数据目录下，因此你可以直接 grep、编辑或删除条目。要查看你机器上的精确路径，运行 `bolt debug paths`。
