Bolt 将每一个 AI 角色都视为一个具名的 **代理**：一个系统提示词搭配一组精确限定的工具权限。你无需为每个任务都运行一个通用模型，而是可以选择访问权限和关注点与你需求相匹配的代理——无论是审计安全、撰写文档，还是完成一次完整的框架迁移。

## 访问级别

每个内置代理都被分配了三种访问级别之一，用于决定它可以调用哪些工具：

| 级别 | 授予的权限 | 典型用途 |
|-------|---------------------|-------------|
| **Full** | 读文件、写/编辑文件、运行 shell 命令 | 主动编程、调试、重构、迁移 |
| **Edit** | 读文件、写/编辑文件——不允许 shell | 文档、注释更新、安全的文本编辑 |
| **Read** | 仅读文件——不允许写、不允许 shell | 规划、研究、代码评审、审计 |

## 内置代理

Bolt 开箱即用提供十个专用代理。在 TUI 中按 <kbd>Tab</kbd> 键即可切换。

| 代理 | 访问权限 | 说明 |
|-------|--------|-------------|
| `code` | Full | 默认：读、写并运行代码 |
| `plan` | Read | 探索代码库并产出计划，不修改代码 |
| `ask` | Read | 提问和研究——不编辑文件 |
| `code-review` | Read | 从正确性、风格和安全性角度评审变更 |
| `debug` | Full | 调试失败的测试、崩溃和逻辑错误 |
| `refactor` | Full | 安全重构，每步都进行测试验证 |
| `docs` | Edit | 编写和更新文档与注释 |
| `security` | Read | 安全审计：漏洞、密钥以及危险模式 |
| `migrate` | Full | 框架升级和依赖迁移 |
| `perf` | Full | 性能分析和优化 |

## 子代理

除了十个主代理之外，Bolt 还内置了两个 **子代理**，主代理在会话中可以将工作委派给它们。你从不需要手动选择子代理——当主代理决定生成子代理时，它们会被自动派发。

| 子代理 | 角色 |
|----------|------|
| `@general` | 需要广泛能力的复杂多步骤任务委派 |
| `@explore` | 快速、只读的代码库研究——遍历文件而不产生副作用 |

<Tip>
  当你需要快速理解不熟悉的代码库时，可以从 `ask` 或 `plan` 代理开始。它们会在幕后派发 `@explore` 子代理以高速索引你的项目，然后再给出答案——完全不需要触碰任何文件。
</Tip>

## 切换代理

**在 TUI 中** — 会话期间随时按 <kbd>Tab</kbd> 循环切换可用代理列表。当前代理会显示在会话底部。

**非交互式** — 向 `bolt run` 传入 `--agent <name>` 可将本次运行固定为特定代理：

```bash
bolt run --agent ask "what does the authentication flow do?"
bolt run --agent security "audit the API layer for injection vulnerabilities"
bolt run --agent docs "add JSDoc comments to every exported function in src/utils"
```

## 列出代理

要查看所有可用的代理——包括内置和自定义——及其模式和权限配置：

```bash
bolt agent list
```

## 自定义代理

你可以通过两种方式创建自己的代理。

### 使用 `bolt agent create` 生成

交互式向导会使用 LLM 生成代理文件并写入磁盘：

```bash
bolt agent create
```

所有标志都是可选的。传入这些标志即可以非交互方式运行：

```bash
bolt agent create \
  --description "Audit GraphQL resolvers for N+1 problems and suggest DataLoader fixes" \
  --path .bolt/agents \
  --mode primary \
  --permissions read,grep,glob \
  --model anthropic/claude-opus-4-5
```

| 标志 | 说明 |
|------|-------------|
| `--description` | 代理应做什么（作为生成时给 LLM 的提示词） |
| `--path` | 写入生成的代理文件的目录 |
| `--mode` | `all`（默认）、`primary` 或 `subagent` |
| `--permissions` | 允许的权限，以英文逗号分隔。省略表示全部允许。 |
| `--model` / `-m` | 使用的模型，格式为 `provider/model` |

### 手动编写 markdown 文件

一个代理其实就是一份带有 YAML frontmatter 的 markdown 文件。将它放在项目内的 `.bolt/agents/` 或全局代理目录中：

```markdown
---
description: "Audit GraphQL resolvers for N+1 problems"
mode: primary
permission:
  bash: deny
  edit: deny
---

You are a GraphQL performance specialist. Your job is to identify N+1 query
patterns in resolver code and recommend DataLoader-based solutions...
```

文件名（不含 `.md`）会成为代理的标识符。

### 可用权限

权限是你在创建自定义代理时可控的细粒度工具开关：

| 权限 | 控制 |
|------------|----------|
| `bash` | Shell 命令执行 |
| `read` | 文件读取 |
| `edit` | 文件写入和编辑（同时管控 `write` 和 `apply_patch`） |
| `glob` | 文件 glob/目录列举 |
| `grep` | 通过 ripgrep 进行文件搜索 |
| `webfetch` | 从 Web 发起 HTTP 请求 |
| `task` | 生成子代理任务 |
| `todowrite` | 创建和更新待办事项 |
| `websearch` | Web 搜索查询 |
| `lsp` | 语言服务器协议操作 |
| `skill` | 访问项目 skills |
