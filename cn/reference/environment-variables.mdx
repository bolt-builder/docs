环境变量让你无需触碰任何配置文件即可配置 Bolt——适合 CI 流水线、Docker 容器以及无法提交凭据的共享环境。它们在启动时读取一次，运行时无法更改。

## 参考

| 变量 | 说明 |
| --- | --- |
| `BOLT_LOG_LEVEL` | 设置日志详细级别。可接受值：`DEBUG`、`INFO`、`WARN`、`ERROR`。等同于 `--log-level` 标志。 |
| `BOLT_PRINT_LOGS` | 设为任意非空值即可将日志输出打印到 stderr。等同于 `--print-logs`。 |
| `BOLT_PURE` | 设为任意非空值即可禁用所有外部插件。等同于 `--pure`。 |
| `BOLT_SERVER_USERNAME` | `bolt serve` 和 `bolt web` 的基本认证用户名。 |
| `BOLT_SERVER_PASSWORD` | `bolt serve` 和 `bolt web` 的基本认证密码。所有连接的客户端都必须提供该密码。 |
| `BOLT_CONFIG` | 覆盖 Bolt 加载的配置文件路径。设置后，Bolt 不会搜索默认位置。 |
| `BOLT_CONFIG_DIR` | 覆盖配置目录。Bolt 会在该目录中查找配置文件，而非默认的操作系统配置目录。 |
| `BOLT_CONFIG_CONTENT` | 以内联 JSON 字符串形式提供完整配置。适合在写入文件不便的 CI 中使用。在配置来源中优先级最高。 |
| `BOLT_GIT_BASH_PATH` | Windows 上 Git Bash 的 `bin` 目录路径，用于定位 `less` 等 Unix 工具。 |

## 提供商 API 密钥

Bolt 会自动从环境变量中发现提供商凭据——无需 `bolt providers login` 步骤。每个提供商查找特定的环境变量，只要变量已设置，Bolt 就会使用它，不论 `auth.json` 中保存了什么。

<Tip>
  在你的 shell 配置（如 `~/.zshrc`、`~/.bashrc`）中设置提供商 API 密钥，或在 shell 加载的 `.env` 文件中设置。你也可以在配置文件的 `provider.*.apiKey` 字段中通过 `${VAR_NAME}` 语法引用它们，从而避免以明文存储密钥。
</Tip>

常见提供商变量：

| 变量 | 提供商 |
| --- | --- |
| `ANTHROPIC_API_KEY` | Anthropic (Claude) |
| `OPENAI_API_KEY` | OpenAI (GPT, o-series) |
| `GOOGLE_GENERATIVE_AI_API_KEY` | Google (Gemini) |
| `OPENROUTER_API_KEY` | OpenRouter |
| `AWS_ACCESS_KEY_ID` \+ `AWS_SECRET_ACCESS_KEY` | Amazon Bedrock |
| `AZURE_OPENAI_API_KEY` | Azure OpenAI |

运行 `bolt models --verbose` 可查看每个已配置的提供商所期望的环境变量。

## 使用示例

```bash
# 对单次运行启用 debug 日志
BOLT_LOG_LEVEL=DEBUG bolt run "why is the auth test failing?"

# 不加载任何插件运行，以排除插件干扰
BOLT_PURE=1 bolt

# 启动带基本认证的公开服务器
BOLT_SERVER_USERNAME=team BOLT_SERVER_PASSWORD=mysecret \
  bolt serve --hostname 0.0.0.0 --port 4096

# 内联提供配置（适合 CI）
BOLT_CONFIG_CONTENT='{"model":"anthropic/claude-opus-4-5"}' \
  ANTHROPIC_API_KEY=sk-ant-xxx \
  bolt run "generate a changelog for this release"
```
