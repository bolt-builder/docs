Bolt 提供四个命令，将你日常的 Git 工作流与 AI 连接起来：一个可以一键安装的 GitHub Actions 代理、一个用于检出拉取请求的快捷方式、一个 AI 提交信息生成器，以及一个具有机器可读退出码的 AI 代码评审器。它们一起让你可以在开发的每个阶段引入 Bolt——本地编程、PR 评审和持续集成。

---

## `bolt github`

管理在 CI 事件上运行 Bolt 的 GitHub Actions 代理。

### `bolt github install`

将 GitHub Actions 工作流安装到当前仓库。这会将工作流 YAML 写入 `.github/workflows/`，使 Bolt 在 issue 评论、新的拉取请求或你配置的其他事件上自动启动。

```bash
bolt github install
```

请在 git 仓库的根目录运行。你需要对 `.github/workflows/` 具备写入权限。

### `bolt github run`

在本地或 CI 步骤中运行 GitHub 代理，回放特定的 GitHub 事件载荷。

```bash
bolt github run --event <event> --token <pat>
```

| 标志 | 说明 |
|------|-------------|
| `--event <event>` | GitHub 事件名，或 JSON 事件载荷的路径 |
| `--token <pat>` | 用于发布评论和获取上下文的 GitHub personal access token（`github_pat_…`） |

## 配置 GitHub Actions 代理

<Steps>
  <Step title="安装工作流">
    在仓库根目录：

    ```bash
    bolt github install
    ```

    Bolt 会将 GitHub Actions 工作流文件写入 `.github/workflows/`。提交并推送该文件。
  </Step>

  <Step title="将 API 密钥添加为 secret">
    在仓库设置中，将你偏好的 LLM 提供商 API 密钥作为仓库 secret 添加（例如 `ANTHROPIC_API_KEY`）。工作流会自动使用。
  </Step>

  <Step title="触发代理">
    在任意 issue 或拉取请求上评论 `/bolt <your request>`。工作流会触发，Bolt 读取事件载荷，并将结果作为回复发布。
  </Step>

  <Step title="本地运行以便调试">
    回放先前工作流运行中的真实事件载荷：

    ```bash
    bolt github run \
      --event path/to/event.json \
      --token github_pat_abc123
    ```
  </Step>
</Steps>

## `bolt pr <number>`

将 GitHub 拉取请求检出到本地分支，并在该分支中启动 Bolt——可以从 PR 作者停下的地方开始评审、调试或继续工作。

```bash
bolt pr 42
```

Bolt 使用 `gh` CLI 获取 PR，创建名为 `pr/<number>` 的分支，并配置上游追踪引用。对于跨仓库（fork）PR，它会自动将 fork 添加为远程。如果 PR 描述包含分享的 Bolt 会话 URL（`opncd.ai/s/…`），该会话会被导入，让你可以继续作者的对话。

> 需要已安装并认证的 [GitHub CLI (`gh`)](https://cli.github.com/)。

## `bolt commit`

根据你的暂存（或全部已跟踪的）改动生成提交信息，并一步完成提交。

```bash
bolt commit
```

Bolt 会对你的改动做 diff，将 diff 连同最近的提交主题（用于风格参考）一起提供给 `commit` 代理，然后用结果运行 `git commit -m <message>`。

### 标志

| 标志 | 别名 | 说明 |
|------|-------|-------------|
| `--all` | `-a` | 提交所有已跟踪的改动，不仅是已暂存的（等同于 `git commit -a`） |
| `--dry-run` | | 打印生成的信息，不进行提交 |
| `--model <provider/model>` | `-m` | 覆盖用于生成信息的模型 |

```bash
# 全部暂存并提交
bolt commit --all

# 预览信息但不提交
bolt commit --dry-run

# 使用特定模型
bolt commit --model anthropic/claude-opus-4-5
```

<Tip>
  使用 `bolt commit --dry-run` 可在提交前预览生成的信息。如果想编辑它，复制输出并运行 `git commit -m "…"`，改为你的措辞。
</Tip>

## `bolt review`

对一个 diff 运行 `code-review` 代理，并以机器可读的判定退出。评审的最后一行始终是 `Verdict: PASS` 或 `Verdict: FAIL`，使 `bolt review` 可以直接接入 CI 流水线。

```bash
bolt review
```

默认情况下，`bolt review` 对 `HEAD` 与工作树进行 diff。使用下方标志可限定 diff 范围。

### 标志

| 标志 | 别名 | 说明 |
|------|-------|-------------|
| `--staged` | | 仅评审已暂存的改动 |
| `--branch <name>` | | 评审自与指定分支的合并基以来的改动（默认为仓库的默认分支） |
| `--model <provider/model>` | `-m` | 用于评审的模型 |

### 退出码

| 代码 | 含义 |
|------|---------|
| `0` | `Verdict: PASS` — 无严重或主要问题 |
| `1` | `Verdict: FAIL` — 发现一个或多个严重或主要问题 |
| `2` | 无法从响应中确定判定结果 |

### 在 GitHub Actions 工作流中使用

```yaml
name: AI Code Review
on:
  pull_request:
    branches: [main]

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Install Bolt
        run: curl -fsSL https://raw.githubusercontent.com/bolt-builder/bolt-cli/dev/install | bash

      - name: AI review
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: bolt review --branch main
```

非零退出码会让检查失败，从而在问题解决前阻止合并。

<Tip>
  在提交前运行 `bolt review --staged`，在问题仍容易修改时发现它们——早于它们进入 PR。
</Tip>
