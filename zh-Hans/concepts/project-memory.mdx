项目记忆使 Bolt 感觉它已经了解你的项目。当会话结束当前轮次时,Bolt 提炼有用的信息并将其写入按项目的记忆存储。当你打开新会话时,Bolt 将记忆索引以及最新会话摘要注入到系统提示中,使代理从真实的上下文开始,而不是从空白起点开始。

## 捕获如何工作

在每次会话轮次结束时,Bolt 要求模型总结下次将有用的持久事实:约定、架构注释、文件布局、构建/测试命令、注意事项和未完成的线索。这些被写入项目记忆目录下的磁盘,与最近会话的滚动摘要一起。

记忆是按项目的。同一台机器上同一仓库的两个 checkout 共享记忆；不相关的项目从不会看到彼此的记忆。

## 显式工具

代理也可以在会话期间直接读写记忆：

- `memory_save` — 记录代理下次应该记住的具体事实。
- `memory_recall` — 查找代理（或你）之前捕获的内容。

你可以让代理"记住我们使用 pnpm，而不是 npm"，它就会为你调用 `memory_save`。

## 按会话控制

在 TUI 内你可以使用斜杠命令切换当前会话的记忆行为：

```text
/memory use on|off         # 此会话是否读取项目记忆
/memory contribute on|off  # 此会话是否写回记忆
```

当你希望进行一次性的探索会话而不污染记忆,或希望进行只读会话但仍受益于之前的上下文时,这很有用。

## 检查和编辑记忆

```bash
bolt memory           # 检查当前项目的记忆存储
```

记忆以纯文件形式存储在项目 Bolt 数据目录下的磁盘上,因此你可以直接 grep、编辑或删除条目。要在你的机器上找到确切路径,请运行 `bolt debug paths`。
