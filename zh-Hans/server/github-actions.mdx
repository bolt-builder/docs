Bolt 提供四个命令,将你的日常 Git 工作流与 AI 连接：一个可以通过单个命令安装的 GitHub Actions 代理、一个用于检出 pull requests 的快捷方式、一个 AI 提交消息生成器,以及一个带有机器可读退出代码的 AI 代码审查器。它们一起让你将 Bolt 带入开发的每个阶段 — 本地编码、PR 审查和持续集成。

---

## `bolt github`

管理在 CI 事件上运行 Bolt 的 GitHub Actions 代理。

### `bolt github install`

将 GitHub Actions 工作流安装到当前仓库。这将工作流 YAML 写入 `.github/workflows/`,以便 Bolt 在 issue 评论、新的 pull requests 或你配置的其他事件上自动启动。

```bash
bolt github install
```

从 git 仓库的根目录运行此命令。你需要 `.github/workflows/` 的写入权限。

### `bolt github run`

在本地或 CI 步骤中运行 GitHub 代理,重放特定的 GitHub 事件有效负载。

```bash
bolt github run --event <event> --token <pat>
```

| 标志 | 描述 |
|------|-------------|
| `--event <event>` | GitHub 事件名称或 JSON 事件有效负载的路径 |
| `--token <pat>` | 用于发布评论和获取上下文的 GitHub 个人访问令牌（`github_pat_…`） |

## 设置 GitHub Actions 代理

<Steps>
  <Step title="安装工作流">
    从你的仓库根目录：

    ```bash
    bolt github install
    ```

    Bolt 将 GitHub Actions 工作流文件写入 `.github/workflows/`。提交并推送该文件。
  </Step>

  <Step title="将 API 密钥添加为密钥">
    在你的仓库设置中,将首选 LLM 提供商的 API 密钥添加为仓库密钥（例如 `ANTHROPIC_API_KEY`）。工作流将自动接收它。
  </Step>

  <Step title="触发代理">
    在任何 issue 或 pull request 上评论 `/bolt <your request>`。工作流触发,Bolt 读取事件有效负载,并发布带有结果的回复。
  </Step>

  <Step title="本地运行以进行调试">
    从之前的工作流运行重放实时事件有效负载：

    ```bash
    bolt github run \
      --event path/to/event.json \
      --token github_pat_abc123
    ```
  </Step>
</Steps>

## `bolt pr <number>`

将 GitHub pull request 检出到本地分支并在该分支中启动 Bolt — 准备好审查、调试或从 PR 作者停止的地方继续工作。

```bash
bolt pr 42
```

Bolt 使用 `gh` CLI 获取 PR,创建一个名为 `pr/<number>` 的分支,并连接上游跟踪 ref。对于跨仓库（fork）PR,它会自动将 fork 添加为远程。如果 PR 描述包含共享的 Bolt 会话 URL（`opncd.ai/s/…`）,则会导入会话,以便你可以继续作者的对话。

> 需要安装并认证 [GitHub CLI (`gh`)](https://cli.github.com/)。

## `bolt commit`

从你的已暂存（或所有已跟踪）更改生成提交消息,并一步完成提交。

```bash
bolt commit
```

Bolt 对你的更改进行 diff,将 diff 连同最近的提交主题作为样式参考一起提供给 `commit` 代理,并使用结果运行 `git commit -m <message>`。

### 标志

| 标志 | 别名 | 描述 |
|------|-------|-------------|
| `--all` | `-a` | 提交所有已跟踪的更改,而不仅是已暂存的更改（等同于 `git commit -a`） |
| `--dry-run` | | 打印生成的消息而不提交 |
| `--model <provider/model>` | `-m` | 覆盖用于生成消息的模型 |

```bash
# 暂存所有内容并提交
bolt commit --all

# 预览消息而不提交
bolt commit --dry-run

# 使用特定模型
bolt commit --model anthropic/claude-opus-4-5
```

<Tip>
  使用 `bolt commit --dry-run` 在提交之前预览生成的消息。如果你想编辑它,请复制输出并使用调整后的措辞运行 `git commit -m "…"`。
</Tip>

## `bolt review`

针对 diff 运行 `code-review` 代理并以机器可读的判定退出。审查的最后一行始终是 `Verdict: PASS` 或 `Verdict: FAIL`,使 `bolt review` 可以即插即用于 CI 管道。

```bash
bolt review
```

默认情况下,`bolt review` 将 `HEAD` 与工作树进行 diff。使用下面的标志来限定 diff 的范围。

### 标志

| 标志 | 别名 | 描述 |
|------|-------|-------------|
| `--staged` | | 仅审查已暂存的更改 |
| `--branch <name>` | | 审查自与命名分支的合并基以来的更改（默认为仓库的默认分支） |
| `--model <provider/model>` | `-m` | 用于审查的模型 |

### 退出代码

| 代码 | 含义 |
|------|---------|
| `0` | `Verdict: PASS` — 没有严重或重大问题 |
| `1` | `Verdict: FAIL` — 发现一个或多个严重或重大问题 |
| `2` | 无法从响应中确定判定 |

### 在 GitHub Actions 工作流中使用

```yaml
name: AI Code Review
on:
  pull_request:
    branches: [main]

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0

      - name: Install Bolt
        run: curl -fsSL https://raw.githubusercontent.com/bolt-builder/bolt-cli/dev/install | bash

      - name: AI review
        env:
          ANTHROPIC_API_KEY: ${{ secrets.ANTHROPIC_API_KEY }}
        run: bolt review --branch main
```

非零退出代码使检查失败,阻止合并直到问题得到解决。

<Tip>
  在提交之前运行 `bolt review --staged` 以在问题仍然容易更改时捕获它们 — 在它们到达 pull request 之前。
</Tip>
