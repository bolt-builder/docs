프로젝트 메모리는 Bolt가 이미 프로젝트를 알고 있는 것처럼 느끼게 만드는 것입니다. 세션이 턴을 종료하면 Bolt는 유용했던 것을 증류하여 프로젝트별 메모리 저장소에 기록합니다. 새 세션을 열면 Bolt는 시스템 프롬프트에 메모리 인덱스와 최신 세션 요약을 주입하므로, 에이전트는 백지 상태 대신 실제 컨텍스트로 시작합니다.

## 캡처 작동 방식

모든 대화 턴이 종료될 때, Bolt는 다음 번에 유용할 지속적인 사실을 요약해 달라고 모델에 요청합니다: 규칙, 아키텍처 노트, 파일 레이아웃, 빌드/테스트 명령, 함정, 미해결 스레드 등. 이는 프로젝트의 메모리 디렉터리 아래에 최근 세션의 롤링 요약과 함께 디스크에 기록됩니다.

메모리는 프로젝트별입니다. 같은 머신의 동일 리포지토리 체크아웃 두 개는 메모리를 공유하며, 관련 없는 프로젝트는 서로의 메모리를 보지 않습니다.

## 명시적 도구

에이전트는 세션 중에도 메모리를 직접 읽고 쓸 수 있습니다:

- `memory_save` — 에이전트가 다음 번에 기억해야 할 특정 사실을 기록합니다.
- `memory_recall` — 에이전트(또는 사용자)가 이전에 캡처한 것을 조회합니다.

에이전트에게 "우리는 npm이 아닌 pnpm을 사용한다는 것을 기억해줘"라고 요청하면 자동으로 `memory_save`를 호출합니다.

## 세션별 제어

TUI 안에서 슬래시 명령으로 현재 세션의 메모리 동작을 토글할 수 있습니다:

```text
/memory use on|off         # 이 세션이 프로젝트 메모리를 읽을지 여부
/memory contribute on|off  # 이 세션이 메모리에 다시 쓸지 여부
```

이는 메모리를 오염시키지 않는 일회성 탐색 세션이나, 이전 컨텍스트의 이점을 여전히 누리는 읽기 전용 세션을 원할 때 유용합니다.

## 메모리 검사 및 편집

```bash
bolt memory           # 현재 프로젝트의 메모리 저장소를 검사
```

메모리는 프로젝트의 Bolt 데이터 디렉터리 아래에 일반 파일로 저장되므로, 항목을 직접 grep, 편집 또는 삭제할 수 있습니다. 머신의 정확한 경로를 찾으려면 `bolt debug paths`를 실행하세요.
