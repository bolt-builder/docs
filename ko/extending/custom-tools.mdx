커스텀 도구를 사용하면 스크립트로 만들 수 있는 어떤 것이든 (셸 스크립트, Node/Bun/Python 프로그램, 작은 바이너리) 에이전트가 이름으로 호출할 수 있는 도구로 노출할 수 있습니다. 이는 Bolt가 프로젝트의 자체 빌드, 배포, 데이터 워크플로에 접근할 수 있게 하는 가장 간단한 방법입니다.

## 파일 위치

다음 중 하나에 파일을 놓으세요:

- `.opencode/tool/` — 프로젝트 범위, 리포지토리에 체크인됨.
- `.opencode/tools/` — 위의 별칭으로 허용됨.

각 파일은 파일 이름(확장자 제외)을 딴 도구가 됩니다. 도구는 Bolt가 다음에 시작될 때 자동으로 감지됩니다.

## 도구의 구조

커스텀 도구는 헤더에서 이름, 설명, 입력 스키마를 선언한 다음 동작을 구현합니다. 정확한 형태는 선택하는 런타임(셸 스크립트, TypeScript 등)에 따라 다르지만, 모든 도구는 반드시:

1. 모델이 호출 방법을 알 수 있도록 입력에 대한 JSON Schema를 알려야 합니다.
2. Bolt가 TUI에 렌더링하고 모델에 다시 전달할 수 있는 값(또는 오류)을 반환해야 합니다.

로드되면, 도구는 `bash`나 `grep` 같은 내장 도구 옆의 에이전트 도구 목록에 나타나고, 동일한 [권한](/concepts/permissions) 시스템에 의해 게이트됩니다.

## 커스텀 도구 vs MCP 서버 사용 시기

- **커스텀 도구** — 작고, 프로젝트별이며, 프로젝트 간 재사용이 없는 경우. 빠르게 작성.
- **MCP 서버** — 프로젝트 간에 공유되거나 인증이 있는 실제 외부 서비스를 감싸는 경우. [MCP Servers](/extending/mcp-servers) 참조.
- **플러그인 도구** — 다른 확장 지점과 함께 npm 패키지로 배포. [Plugins](/extending/plugins) 참조.
