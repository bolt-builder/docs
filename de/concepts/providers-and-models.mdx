Bolt ist von Grund auf modellagnostisch. Unter der Haube verwendet es das **Vercel AI SDK**, um mit Providern zu kommunizieren, was bedeutet, dass jeder vom SDK unterstützte Provider – Anthropic, OpenAI, Google, Amazon Bedrock, OpenRouter und mehr – sofort funktioniert. Der Katalog der Provider und Modelle stammt von [models.dev](https://models.dev), einer von der Community gepflegten Datenbank mit Provider-Metadaten und Preisen.

## Provider-Zugangsdaten verwalten

Verwenden Sie `bolt providers` (Alias: `bolt auth`), um Provider-Zugangsdaten hinzuzufügen, aufzulisten und zu entfernen.

### Zugangsdaten hinzufügen oder aktualisieren

```bash
bolt providers login
# or equivalently:
bolt auth login
```

Dies startet einen interaktiven Prompt zum Auswählen eines Providers und Eingeben von Zugangsdaten. Um den interaktiven Ablauf zu überspringen, übergeben Sie Flags direkt:

```bash
bolt providers login --provider anthropic
bolt providers login --provider openai --method "API key"
```

### Konfigurierte Provider auflisten

```bash
bolt providers list
# or:
bolt auth list
```

Zeigt alle gespeicherten Zugangsdaten und alle Provider-API-Schlüssel an, die aus Umgebungsvariablen erkannt wurden.

### Zugangsdaten entfernen

```bash
bolt providers logout
bolt providers logout anthropic
```

### Authentifizierung per Umgebungsvariable

Für CI-Pipelines oder Headless-Umgebungen setzen Sie die API-Schlüssel-Umgebungsvariable des Providers direkt – kein interaktives Login erforderlich. Häufige Beispiele:

```bash
export ANTHROPIC_API_KEY="sk-ant-..."
export OPENAI_API_KEY="sk-..."
export GOOGLE_GENERATIVE_AI_API_KEY="AIza..."
```

Bolt liest diese Variablen beim Start automatisch. `bolt providers list` zeigt an, welche Umgebungsvariablen erkannt wurden.

## Verfügbare Modelle durchsuchen

`bolt models` listet jedes Modell auf, das über Ihre konfigurierten Provider verfügbar ist.

```bash
# List all models
bolt models

# Filter to one provider
bolt models anthropic

# Show cost and capability metadata
bolt models --verbose

# Refresh the model catalog from models.dev
bolt models --refresh
```

<Tip>
  Führen Sie `bolt models --verbose` aus, um Input-/Output-Token-Preise für jedes Modell zu sehen. So lassen sich Kosten-Kompromisse leicht vergleichen, bevor Sie sich für ein Modell für eine lang laufende Aufgabe entscheiden.
</Tip>

### Format des Modellbezeichners

Modelle werden immer im Format `provider/model` referenziert:

```
anthropic/claude-opus-4-5
openai/gpt-4o
google/gemini-2.5-pro
openrouter/anthropic/claude-opus-4-5
```

Verwenden Sie dieses Format überall dort, wo Bolt ein Modell akzeptiert – CLI-Flags, Konfigurationsdateien und Agent-Definitionen.

## Ein Modell zur Laufzeit auswählen

### Flag `--model` / `-m`

Das Flag `--model` steht bei `bolt run`, `bolt commit` und `bolt review` zur Verfügung:

```bash
bolt run --model anthropic/claude-opus-4-5 "refactor the payment module"
bolt commit --model openai/gpt-4o
bolt review --model google/gemini-2.5-pro --staged
```

### `--variant` – Reasoning-Aufwand steuern

Einige Modelle unterstützen konfigurierbare Reasoning-Aufwandsstufen (z. B. Extended Thinking von Anthropic, Reasoning-Modelle von OpenAI). Verwenden Sie `--variant`, um die Aufwandsstufe zu wählen:

```bash
bolt run --variant high "design a distributed rate limiter"
bolt run --variant minimal "rename this variable"
```

<Note>
  Die verfügbaren Variantenwerte hängen vom Provider und Modell ab. Häufige Werte sind `minimal`, `low`, `medium`, `high` und `max`, aber der genaue Satz variiert. Prüfen Sie die Dokumentation Ihres Providers oder verwenden Sie `bolt models --verbose`, um die unterstützten Varianten eines Modells zu sehen.
</Note>

### `--thinking` – Reasoning-Blöcke anzeigen

Wenn Sie ein Modell verwenden, das Extended Thinking unterstützt, übergeben Sie `--thinking`, um die Gedankenkette des Modells in der Ausgabe sichtbar zu machen:

```bash
bolt run --model anthropic/claude-opus-4-5 --variant high --thinking \
  "why does the token refresh logic race in the auth service?"
```

## Best-of-N-Parallelläufe

`--best-of` sendet denselben Prompt parallel an mehrere Modelle und verwendet dann ein Judge-Modell, um die Antworten zu bewerten und die beste zu behalten:

```bash
bolt run --best-of "anthropic/claude-opus-4-5,openai/gpt-4o,google/gemini-2.5-pro" \
  "implement a binary search tree with full test coverage"
```

Als Judge wird standardmäßig das über `--model` übergebene Modell verwendet, oder der erste Eintrag in der `--best-of`-Liste, falls `--model` nicht gesetzt ist. Das Flag akzeptiert eine kommagetrennte Liste von `provider/model`-Bezeichnern.

<Tip>
  Best-of-N ist besonders nützlich für komplexe algorithmische Probleme oder Architekturentscheidungen, bei denen unterschiedliche Modelle wirklich unterschiedliche Ansätze verfolgen können. Lassen Sie Bolt sie parallel ausführen und automatisch den Gewinner auswählen.
</Tip>
