Bolt 的設計本質上就是模型無關的。在底層,它使用 **Vercel AI SDK** 與供應商溝通,這代表 SDK 支援的任何供應商 — Anthropic、OpenAI、Google、Amazon Bedrock、OpenRouter 等等 — 都能開箱即用。供應商與模型目錄來自 [models.dev](https://models.dev),一個由社群維護的供應商中繼資料與定價資料庫。

## 管理供應商憑證

使用 `bolt providers`(別名為 `bolt auth`)來新增、列出與移除供應商憑證。

### 新增或更新憑證

```bash
bolt providers login
# or equivalently:
bolt auth login
```

這會啟動互動式提示以選擇供應商並輸入憑證。若要略過互動流程,可直接傳入旗標:

```bash
bolt providers login --provider anthropic
bolt providers login --provider openai --method "API key"
```

### 列出已設定的供應商

```bash
bolt providers list
# or:
bolt auth list
```

顯示所有已儲存的憑證,以及從環境變數偵測到的任何供應商 API 金鑰。

### 移除憑證

```bash
bolt providers logout
bolt providers logout anthropic
```

### 環境變數驗證

對於 CI pipeline 或無介面環境,可直接設定供應商的 API 金鑰環境變數 — 無需互動式登入。常見範例:

```bash
export ANTHROPIC_API_KEY="sk-ant-..."
export OPENAI_API_KEY="sk-..."
export GOOGLE_GENERATIVE_AI_API_KEY="AIza..."
```

Bolt 會在啟動時自動讀取這些變數。`bolt providers list` 會顯示它偵測到哪些環境變數。

## 瀏覽可用模型

`bolt models` 會列出你已設定供應商中所有可用的模型。

```bash
# List all models
bolt models

# Filter to one provider
bolt models anthropic

# Show cost and capability metadata
bolt models --verbose

# Refresh the model catalog from models.dev
bolt models --refresh
```

<Tip>
  執行 `bolt models --verbose` 可查看每個模型的輸入/輸出 token 定價。這讓你在為長時間任務決定使用某個模型前,能輕鬆比較成本取捨。
</Tip>

### 模型識別碼格式

模型永遠以 `provider/model` 格式參考:

```
anthropic/claude-opus-4-5
openai/gpt-4o
google/gemini-2.5-pro
openrouter/anthropic/claude-opus-4-5
```

在 Bolt 接受模型的任何地方 — CLI 旗標、設定檔與代理定義 — 都使用此格式。

## 在執行時選擇模型

### `--model` / `-m` 旗標

`--model` 旗標可用於 `bolt run`、`bolt commit` 與 `bolt review`:

```bash
bolt run --model anthropic/claude-opus-4-5 "refactor the payment module"
bolt commit --model openai/gpt-4o
bolt review --model google/gemini-2.5-pro --staged
```

### `--variant` — 控制推理強度

有些模型支援可設定的推理強度等級(例如 Anthropic 的延伸思考、OpenAI 的推理模型)。使用 `--variant` 選擇強度層級:

```bash
bolt run --variant high "design a distributed rate limiter"
bolt run --variant minimal "rename this variable"
```

<Note>
  可用的 variant 值取決於供應商與模型。常見值為 `minimal`、`low`、`medium`、`high` 與 `max`,但確切的集合會有所不同。請查閱你的供應商文件,或使用 `bolt models --verbose` 查看指定模型支援的 variant。
</Note>

### `--thinking` — 顯示推理區塊

使用支援延伸思考的模型時,傳入 `--thinking` 可在輸出中顯示模型的思考鏈:

```bash
bolt run --model anthropic/claude-opus-4-5 --variant high --thinking \
  "why does the token refresh logic race in the auth service?"
```

## Best-of-N 平行執行

`--best-of` 會將相同的提示平行送到多個模型,然後使用評審模型為回應排名並保留最好的一個:

```bash
bolt run --best-of "anthropic/claude-opus-4-5,openai/gpt-4o,google/gemini-2.5-pro" \
  "implement a binary search tree with full test coverage"
```

評審預設為透過 `--model` 傳入的模型,若未設定 `--model`,則為 `--best-of` 清單中的第一個項目。此旗標接受以逗號分隔的 `provider/model` 識別碼清單。

<Tip>
  Best-of-N 對於不同模型可能帶來截然不同做法的複雜演算法問題或架構決策特別有用。讓 Bolt 平行執行它們並自動挑選勝出者。
</Tip>
